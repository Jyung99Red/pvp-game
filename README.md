# 放置地牢

方块风格的 3D 动作 RPG，在手机浏览器里横屏玩。项目使用原生 HTML、CSS 和 JavaScript，没有打包器和安装步骤；3D 画面用 three.js（已放在 `vendor/three/`，离线可用）。

**正在重建。** 2D 竖屏版本在标签 `v1-2d`（提交 `2a313c4`）。重建按 [docs/tasks/rebuild-plan.md](docs/tasks/rebuild-plan.md) 分 6 个里程碑进行，现在完成到 **M4 PVP 对战**：横屏外壳、五个按钮的输入层、主角走路和跑步、8 招连段、骨骼判定、盾和格挡条、训练木桩，野外的哥布林和野狼（巡逻、发现、追击、出招、狂暴）和胜负结算，以及两台手机的联机对战（房间号、主机判定、视野遮挡）。据点和装备界面会在后面的里程碑里回来。

## 开始运行

Windows 下直接双击项目根目录的 [Run-Game.bat](Run-Game.bat)。脚本会启动本地服务并在默认浏览器打开游戏；保持脚本窗口开启即可继续游玩，关闭窗口会停止服务。

服务监听所有网卡。手机和电脑连在同一个网络时，用脚本窗口里“Phone on the same network”那一行的地址在手机浏览器打开即可。

脚本需要系统已安装 Python，并会自动尝试 `py` 和 `python`。也可以在项目目录手动运行：

```powershell
python -m http.server 8422
```

然后打开 [http://localhost:8422](http://localhost:8422)。资源通过 `fetch()` 和 `import()` 加载，不能直接用 `file://` 打开 `index.html`。

## 操作

只支持横屏，竖屏时会提示把手机横过来。Android 上第一次触摸会请求全屏。

| 操作 | 触屏 | 键盘 |
|---|---|---|
| 移动 | 左下角区域按下出现摇杆，拖动；连续走 2 秒后自动变成跑 | WASD 或方向键 |
| A | 右下大按钮 | J |
| B | A 上方 | K |
| 副手（现在是盾） | A 左边（显示当前副手的图标） | L |
| 交互 | 左上方（还没有可交互的东西） | E |
| 菜单（暂停、重新开始、换场地、联机对战） | 左上角小方键 | Esc |

最多同时两个触点（左右拇指）。底部正中显示帧率、绘制调用次数和三角形数量，方便在手机上看性能。

## 场地

- **野外**（默认）：2 只哥布林、2 只野狼在各自的家附近巡逻。走进发现距离，它们会停一下、头上出"!"，然后追过来轮流出招；出招前地上会出现红色预警区，越来越浓，躲开或举盾。
  生命降到三成会狂暴（更快、更痛）。把它们全打倒就是胜利；主角生命打空就是失败。结算后可以再来一次或去训练场。
- **训练场**：从菜单进。训练木桩站在空地东边，主角走近 3 格以内它就轮流出招（快斩、重击）。木桩和主角在训练场都不会倒下，打空会回满。

地址后加 `?map=field` 或 `?map=clearing` 可以直接进指定场地，加 `?boxes` 可以看到判定盒。

## 联机对战

两台手机对打，公平对决：双方属性相同，都拿剑和盾（不能带药水）。

1. 两台手机都打开游戏，并且都能上网：配对要经过 PeerJS 的免费公共服务器，配对之后两台手机直接互传数据。
   在同一个 Wi-Fi 下，两台手机都可以打开电脑上 `Run-Game.bat` 显示的那个地址。
2. 一台点左上角菜单 →"联机对战"→"创建房间"，屏幕上出现 4 位房间号。
3. 另一台点"联机对战"→"加入房间"，用数字键盘输入房间号，点"加入"。
4. 连上后两边自动进竞技场，倒计时 3 秒开打。创建房间的一方是主机，所有命中都由主机判定。

- 每台手机都把自己画成蓝衣、对方画成红衣。墙后看不见的对手不画，自己看不见的地面会变暗；对手在视线里但跑出屏幕时，屏幕边缘有红色箭头指着他。
- A 招打中对方只扣血、不打断，双方可以互换轻击；B 招打中会打断对方的连段并把人推开。盾、弹反和打怪时一样。
- 对局不会暂停，菜单里可以认输或离开。手机切到后台（包括锁屏）会结束这一局并通知对方；5 秒收不到对方的消息算断线，都会提示原因。
- 一局结束后两边都点"再来一局"就重新开始。

在一台电脑上试：开两个标签页，地址都加 `?link=local`，两个标签页直接对战，不用联网。
公共服务器连不上时，可以自己搭一个 [PeerServer](https://github.com/peers/peerjs-server)，两边地址都加 `?peer=主机:端口`。

## 战斗

出招是一棵派生树：每一段都是独立的一招，有前摇、挥动、后摇；下一段出哪一招，由 **A、B、停顿** 决定。
只有挥动段的武器碰到身体才算命中，判定跟着 3D 模型的骨骼走。

| 输入 | 招式 |
|---|---|
| A → A A → A A A | 横扫 → 回扫 → 回旋斩（收尾，约 210°） |
| A A ·（停一下）A | 连刺 |
| A B / A A B | 上挑 / 下劈（击退并累积失衡） |
| B（按住蓄力，松手出招）→ B A | 蓄力斩 → 追斩 |

- A、B 按下立刻出招。出招中提前按的下一下会缓冲（只留最后一个），到派生点接上；按得早不会让招变快。
- 连段中摇杆只转向，不移动；后摇结束时还推着摇杆就走开，连段中断。
- 后摇结束后故意停一下，等剑闪白（停顿线）再按 A，出的是连刺。
- **盾**：按住副手键举盾，可以慢慢走；盾刚举起的一小段时间内挡下 = 完美弹反（反击并给对方失衡）。
  举盾会扣格挡条，按住持续扣，挡下一击按伤害扣；扣空后要回到四成才能再举。蓄力中按副手键会丢掉蓄力、立刻举盾；
  出招中按下要等这一招的后摇结束才举起（这期间按 A、B 不出招，松开副手键就取消）。
- 失衡满 3 点，木桩或怪物硬直 1.5 秒。只有 B 招和完美弹反给失衡；B 招还会把怪物击退。怪物不会被打出硬直，挨打时照样出招。
- 跑步时出招会站定，举盾会变成慢走，都会结束跑步。
- 隔着石头、墙，双方都打不到对方。

| 怪物 | 招式 |
|---|---|
| 哥布林 | 乱挥（右到左横扫，范围宽、距离近）、猛扑（举棍跳过来往下砸，距离远一些） |
| 野狼 | 撕咬（近身咬）、扑击（从约 4 格外整个身体扑过来，预警是一条长带） |

## 测试

```powershell
node --test "tests/*.test.cjs"
```

Node 测试覆盖启动器、矩阵和盒子相交、骨骼和正向运动学、走路和跑步、模拟循环、移动和碰撞、按钮布局、连段、盾和格挡条、骨骼判定（每招在标准距离必中、扫角符合设计）、怪物（模型尺寸、对矮个子野狼必中、怪物出招的射程和红区、巡逻发现追击出招、狂暴、拴绳、墙挡刀、整场胜负）、联机对战（主角互打的规则、同一步互砍和平局、快照检查，以及主机和访客两端的协议：握手、倒计时、预测、认输、再来一局、断线）。`tests/browser-smoke.test.cjs` 在装了 Playwright 时用无头浏览器打开真实页面（横屏加载、画面、实时打木桩、竖屏提示、两指同时操作、野外打到结算、菜单换场地、两个页面用 `?link=local` 打完一局对战），没装时跳过。手感、真实帧率、音效、iPhone 行为仍要在真机上检查。

## 项目结构

```text
core/       模拟和数学（不依赖页面和 three.js）、联机对战的协议、启动器
models/     模型数据：骨架、方块、装备、关键姿势、调色板
render/     three.js 画面
ui/         输入层、启动和界面（含联机房间）
net/        联机通道（PeerJS 和同一浏览器两个标签页之间的本地通道）
vendor/     第三方文件（three.js、PeerJS）
partials/   启动时挂载的页面片段
tests/      Node 测试和浏览器冒烟测试
```

进行中的设计在 `docs/tasks/`。新增或删除脚本、样式及页面片段时，要同步更新 `client-assets.json`。
