# 参数表

`game_config.js` 的对照表，数值以它为准；改了数值顺手改这里。规则是怎么定的、为什么，看 `design.md`。

**单位**：距离和速度用世界单位（1 格 = 40），速度是每秒；时间是秒；角度是弧度；触屏上的尺寸是 CSS 像素；模型和镜头用格。

## 0. 不在 `game_config.js` 里的

| 在哪 | 是什么 |
|---|---|
| `models/` | 骨架、方块、颜色名、装备方块、所有关键姿势。是素材不是数值：招式的形状和射程由姿势决定，测试钉住 |
| `core/loop.js` | 模拟步长 0.01 秒，单帧最多补 0.1 秒 |
| `core/terrain.js` | 分块 16×16；树 4 格高、建筑和传送门 3 格、枯木丛 2 格、矿石和晶石 1 格 |
| `core/duel.js` | 联机协议版本 `PROTOCOL` = 7（改协议时手动加一）；访客最多攒 256 条未确认的操作 |
| `render/` | 没搬进 `graphics` 的画面的数：色调映射 Neutral；离镜头 18 格外不画；视野阴影的边缘模糊 `BLUR` 1.1 个贴图像素步长、贴图 256；太阳影子贴图 2048 以上取样 `SUN_TAPS` 12 个；镜头遮挡透明的半径 1.3 格、开合约 0.2 秒；光照探针 `PROBES`（`render/terrain_light.js`）。其余画面的数在第 9 节 |
| `ui/hud.js` | 昼夜表 `CLOCK`：外圈分 48 段，每段按那个钟点的光（`day.looks`）上色，白天绿、日出日落橙、夜里蓝 |
| `net/link.js` | 房间号 4 位数字、STUN 服务器 |

## 3. 招式 `combo`

| 参数 | 值 | 说明 |
|---|---:|---|
| `windowAfterRecovery` | 0.7 | 后摇放完后连段还能接多久 |
| `bufferSeconds` | 0.5 | 预输入多久没执行就作废（卡肉不算） |
| `holdSeconds` | 0.2 | 一个攻击键出 A 和 B（用户 2026-10-03）：这之前松手是 A，按住这么久是 B；判定用掉的时间算进前摇，招的总时长不变 |
| `windupTurnMultiplier` | 1/3 | 前摇里摇杆能转身，转速是平时的 1/3；挥动开始时方向锁定（用户 2026-10-02） |
| `weapons.sword` | 起手 A 斜斩、B 蓄力斩；标准距离 60；停顿 0.15 | 剑。停顿：后摇放完再过这么久才算"停顿"（用户 2026-10-02：从 0.2 缩短一点） |
| `weapons.dagger` | 起手 A 斜切、B 突刺；标准距离 48；停顿 0.2 | 短刃 |

出招中摇杆不走；只有前摇里能慢慢转身（1/3 转速），挥动和后摇里都不能转（用户 2026-10-02）。后摇放完还推着摇杆就走开，连段中断。

标准距离：这种武器的每一招都必须在这个中心距离打中木桩、人形、哥布林、野狼、洞穴蜘蛛和首领（测试）。

下面两张表：时间是 前摇 / 挥动 / 后摇，派生点从挥动结束算起（"—"是收尾招）；倍率乘攻击力；踏步是挥动时身体移动的距离（负数往后）。

`standOff` 0.85：两招之间的间隔里，慢慢（巡逻速度）靠到近段边缘的 85% 就站住。`corpseSeconds` 2.5：倒下躺多久再沉下去。`riseSeconds` 1.2：在坟墓复活的首领从地下升上来要多久，这段时间打不到它。

锁定：前摇最后这么多秒不再跟着主角转（锁定算在前摇里，不另外加时间）；撕咬只锁最后 0.12～0.17 秒，侧走会被它跟上。冷却：从前摇开始算，按怪物自己的时钟走（狂暴时一起变快）。
出手距离和地上的红区都由动作扫出来，不是参数；近表的招在主角进了"不算踏步"的距离才出，踏步用来追后退的主角。
刺足：两条前腿举高再往正前方扎下，红区约一格宽（左右各约 0.48 格）；踏步 40，从近处后退躲不开，侧走躲得开（测试）。
撕咬摆头：头从一边扫到另一边（头左右各约 0.55、身子约 0.2 弧度），每次随机从左或从右起，红区是两边合起来的小扇形（左右各约 0.9 格，狼王约 1.1 格）。

快慢的范围（用户 2026-10-03 拉大）：轻招快、空档短，重招慢、空档长。之后用户试玩（连段后摇里有时来不及挡）又把小怪（哥布林、野狼）

最慢的是头目震地 1.5 秒。每一下都要挡得住：看到红区 0.35 秒（`reactSeconds`）后按格挡键，举起要 0.16 秒，狂暴时也来得及（测试检查）。
