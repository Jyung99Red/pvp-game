## 1. 一句话

整个游戏改为横屏。竖屏下"中央键 + 左侧防御 + 右侧技能盘"的布局废弃，
换成约 5 个按钮：**移动摇杆、A、B、副手键、交互键**。技能系统整体放弃。

## 2. 已定

| 项 | 决定 |
|---|---|
| 屏幕 | 横屏 |
| 按钮 | 约 5 个，包括移动 |
| 攻击 | 拆成 A、B 两个键；招式派生树不变（轻、重、停顿） |
| 防御键 → 副手键 | 功能由副手装备的类型决定：盾 = 举盾防御，火把 = 点火，药水 = 喝 |
| 交互键 | 新增；可以和盾牌防御叠加（同时有效） |
| 技能 | 完全放弃：治疗、疾速、满蓄、弹反技能和 SP 都删除 |
| 副手键的名字 | 叫"副手键"（代码里是 `offhand`）；按钮上显示当前副手的图标，不写字 |
| 换副手 | 战斗中不能换，只在装备界面换；带什么副手是出战前的取舍 |
| 副手空着 | 副手键灰掉不响应；以后空手有了功能再加 |
| 存档 | 不考虑旧存档 |

## 3. 布局（暂定，要在真机上调）

```
┌──────────────────────────────────────────────────────┐
│ [暂停]       血量 · 格挡条 · 敌人血量          [设置] │
│                                                      │
│                       游戏画面                        │
│                                                      │
│  [交互]                                      [ B ]   │
│    摇杆（浮动，按在左半屏任意处出现）     [副手][ A ]  │
└──────────────────────────────────────────────────────┘
```

- **左手**：摇杆和交互键。摇杆是浮动的，按在左半屏任意处出现，沿用现在的 `data-origin-at-press`。
- **右手**：A、B、副手键，围着右下角的拇指落点排成弧形。
  A 最大、最顺手；B 在 A 的上方；副手键在 A 的左边。
  A 和 B 来回按得最频繁（`T T H`、`T H`），所以紧挨着；格挡之后接反击是副手键到 A，也顺。
- **交互键放左手**的原因见 4.5：这样"举盾 + 交互"只要两个拇指。
- 尺寸初值（CSS 像素）：A 84，B 和副手键 72，交互键 56，按钮间距不小于 10，
  离屏幕边缘用安全区（`env(safe-area-inset-*)`）。横屏手机的高度只有约 360～430，右侧按钮簇总高度要控制在 200 以内。
- 布局做成数据（`game_config.js` 里的 `controlsLayout`），位置和大小以后随时可调；
  设置里提供左右手镜像。
- 桌面键盘（以后加，成本很小，调试和测试也方便）：WASD 移动，J = A，K = B，L = 副手键，E = 交互。

## 4. 五个操作

### 4.1 移动

- 浮动摇杆，沿用现在的死区（12）、加速段（32）和"连段中拖动只转向"。
- 现在一个键既移动又出招，要靠"一开始就拖动 = 移动，原地按住 = 长按"来区分；
  摇杆独立之后这类歧义全部消失，"拖动永远是移动"天然成立。
- 连段中摇杆只转向，沿用。左手转向、右手按 A 或 B 可以同时进行，
  不再需要"拖动转向 → 松手 → 再轻点"，所以 `combat-combo-concept.md` 第 11 节待定 1 自然解决。

### 4.2 A 和 B：攻击拆成两个键

招式表里仍然记 `T`、`H`、停顿，键名 A、B 只是界面叫法（也可以换成图标）。

| 现在（一个中央键） | 新 |
|---|---|
| 轻点 `T` | 点按 A |
| 起手的轻点要等松手才能知道不是长按，所以松手才进前摇 | 按下 A **立刻**进前摇 |
| 连段中间长按 `H`：先按住不动 0.25 秒进入蓄势，松手或满 0.25 秒后出招 | 点按 B：到派生点直接出 `H` 招，没有蓄势 |
| 起手长按 = 蓄力斩：按住蓄力，松手出招 | 起手按住 B 蓄力，松手出招 |
| 停顿后轻点 | 停顿后点 A |

好处：

- 起手手感更即时，不再多等一个点按的时间。
- 删掉蓄势状态及其参数（`combo.poiseSeconds`，`input.holdSeconds` 的这一用途）和"起手 `T` 要等松手"的规则；
  `core/combat_gestures.js` 里"待定 / 蓄力 / 蓄势"的区分大幅简化。
- 击退和硬直仍是每招自己的属性（每招自带击退距离和失衡值，见 `3d-migration-concept.md` 第 5 节）。暂时恰好 B 招都有、A 招都没有，但不写死成"按 B 就击退"，以后可以有不击退的 B 招，或击退的 A 招。
- 预输入（只留最后一个、0.4 秒作废）、停顿线、派生点这些规则不变，只是输入来源变成 A 和 B。

细节（暂定，实现时对照现有蓄力参数）：

- **蓄力斩时间轴**：按下 B 立刻起手进前摇；前摇结束后仍按住就进入蓄力，松手出招；
  前摇结束前松手，前摇一结束就出招（最小蓄力）。蓄力伤害的起算点沿用 `chargeThresholdMs`（含武器偏移）。
  蓄力中可以移动、转向，沿用。蓄力中按副手键（举盾）丢掉蓄力，沿用。
- 长按 A 没有含义，先留空。

### 4.3 副手键

副手键只有一个，**做什么由副手装备的类型决定**：

| 副手 | 按下 | 按住 | 松开 | 状态 |
|---|---|---|---|---|
| 盾 | 举盾；按下后很短时间内挡下 = 完美弹反 | 持续举盾，慢扣格挡条，可慢速移动 | 放下盾 | 规则原样搬来（格挡条、弹反窗口、空条锁定）；2026-10-01 改为不能打断后摇，出招中按下要等后摇结束 |
| 火把 | 点燃或熄灭手持火把 | 待定 | 无 | 意图已定，细节待定（见第 8 节） |
| 药水 | 喝一口：约 0.8 秒的动作，消耗一瓶，回复生命 | 无 | 无 | 意图已定，数值待定 |
| 空手 | 无，按钮灰掉 | | | 已定；以后空手有了功能再加 |

实现上，副手类型是一张**行为表**：每种类型有自己的按下、按住、松开处理和一组动画，
引擎按副手类型派发。现在的举盾防御代码整体变成"盾"这一项，其余类型各自加一项，不动结构。
以后加新类型（双刀、法器之类）只是多一行，但每个新类型都要回答"没有盾时怎么防御"。
双刀的暂定答案是交叉格挡（格挡条更小，或没有弹反加成），而且双刀占用副手、不能带盾；弓、弩因为触屏没有瞄准操作，暂不考虑。

要提前知道的后果：**副手不是盾，就没有防御**。
格挡条、完美弹反、"格挡能打断后摇"都是盾的特性，而怪物的招式都是围绕"挡或躲"设计的。
带火把或药水的人只能靠走位。**战斗中不能换副手**（已定），所以带什么副手是出战前的取舍：探索带火把，打首领带盾。

### 4.4 交互键

- **据点**：靠近建筑时亮起，按下进入（代替现在的"点中央键"）。
- **野外**：采集、开箱、开门、拾取。耗时的动作（采集）按住读条。
- **战斗中**：暂时无效（灰色）。以后可以给它盾击、闪避之类，但这一轮不定。
- 和盾叠加：两个键的状态互不排斥，举盾期间按交互照样生效。
  现在 `press()` 里"除了移动，别的通道按下时有技能手势就拒绝"之类的互斥规则要放宽。
- 提示和目标选择走统一的"可交互目标"（见 `3d-migration-concept.md` 第 15 节）：
  范围内按距离和朝向选一个，显示提示。

### 4.5 手指够不够用

一个触点对应一根手指。同一根拇指压住相邻的两个键，浏览器也只给一个触点，不能同时触发两个键。
所以设计成：**左拇指管摇杆或交互键，右拇指管 A、B 或副手键，任何组合最多同时 2 个触点**
（和现有 `pointers.size >= 2` 的限制一致）。

| 组合 | 手指 | 说明 |
|---|---|---|
| 移动 + A 或 B | 左 + 右 | 连段中左手转向，右手出招 |
| 移动 + 举盾 | 左 + 右 | 举盾慢速移动，沿用 |
| 举盾 + 交互 | 右 + 左 | 左拇指离开摇杆去点交互键；交互时通常站着不动，不需要同时移动 |
| A 和 B 一起按 | — | 同一根拇指，也没有需要 |
| 副手键和 A、B 一起按 | — | 沿用现有互斥：举盾期间点 A、B 不出招；攻击中按副手键，后摇里立刻举盾，前摇和挥动里等挥完再举盾 |

如果把交互键放在右侧按钮簇里，"举盾 + 交互"就要第三根手指。你说"可能和盾叠加"，放左手可以不靠第三根手指实现，所以暂定放左手。

## 6. 横屏对界面的影响

**现状**：界面按竖屏手机设计。`style.css` 把页面限宽 480px，底部有"冒险 / 玩家对战"导航栏，顶部有时间条；
战斗视图是铺满全屏的（`position: fixed; inset: 0`），控制区固定在底部，高 166px；
据点、背包、商店、铁匠铺是宽不超过 540px 的对话框。已有一条 `max-height: 480px` 的矮屏规则，说明矮屏做过一点适配。
全部 CSS 和页面片段合计约 1250 行。

> 2026-10-01：整体按重做处理，旧界面不迁移。下面列的是新界面要满足的要求。

**要做**：

1. **外壳**：去掉 480px 限宽，横屏铺满。横屏高度只有 360～430，顶部时间条和底部导航栏占掉太多，要改成收进菜单或放到侧边。
2. **方向**：Android Chrome 要先进入全屏才能用 `screen.orientation.lock('landscape')`；
   iPhone 的 Safari 就我所知不支持锁定方向，也不支持让网页全屏（添加到主屏幕后可接近全屏）。
   所以：竖屏时显示"请旋转手机"遮罩，横屏后才进游戏；Android 上第一次触摸时顺便请求全屏。以真机验证为准。

5. **PVP 竞技场**：现在是竖向 570×630，改成横向布局，场地、出生点、墙都要重做，布局版本号上调。
6. **取景**：横屏画面更宽更矮，左右多看，前后少看。怪物警戒距离、PVP 对手可见性、3D 镜头取景都要重新看。

## 10. M1 落地时补的决定（2026-10-01）

文档里没写到、按最简单的做法定下的，以后可以改：

- **全屏**：第一次触摸**松手**时请求全屏（触屏的按下不算用户操作，浏览器会拒绝），进入全屏后再锁横屏。
  只请求一次，用户退出全屏后不再打扰。iPhone 的 Safari 没有这个接口，直接跳过，竖屏靠旋转提示。
- **竖屏**：用 CSS 的方向查询显示"请把手机横过来"盖住全屏；竖屏时不画 3D 画面，省电。
- **摇杆**：底座半径 52（也是摇杆头最远位置）；没按时摇杆淡淡地停在左下 (120, 96)，告诉玩家在哪。
  能按出摇杆的区域：起初是左半屏整个高度，2026-10-01 真机试用后用户觉得太大，改成左下角约 250×190 的一块（`controlsLayout.stick`）。
  摇杆不跟随手指漂移（手指拖出底座外，方向照算，摇杆不动）。
- **按钮外观**：A、B 用字母，A 用强调色描边；副手键显示盾的图标；交互键写"交互"两个字（待定第 7 条的暂定）。
- **交互键在 M1**：还没有可交互的东西，按钮半透明（"没有目标"的样子），按下照样有反馈、照样发命令，方便试位置。
- **触点规则**：同一个按钮同时只认一个触点；第三根手指不响应；同一个按钮被键盘和触屏同时按住，只算一次按下。
- **窗口大小变化**：只重新排布按钮，不松开按住的摇杆和按钮（第一次触摸后进入全屏会触发一次，不能让还在走路的左手失灵）。
  真正转屏时浏览器自己会取消触点。切到后台或失去焦点时才全部松开。
- **性能显示**：左上角一直显示帧率、绘制调用次数、三角形数量，方便在真机上看。以后放进设置里开关。
- **键盘**：方向键和 WASD 都能移动。

## 11. M2 落地时补的决定（2026-10-01）

- **A**：按下立刻进前摇。**起手 B**：按下立刻进蓄力斩的前摇；前摇结束时还按着就进入蓄力，松手出招；前摇结束前已松手，前摇一结束就出招（最小蓄力）。
  蓄力时长从按下那一刻算（4.2 节"起算点沿用 chargeThresholdMs"）；蓄力不会自己出招，只能松手或举盾丢掉。
- **连段中间的 B**：到派生点直接出该节点的 B 招，没有蓄势。没有 B 派生的节点按起手 B（蓄力斩）处理。
- **预输入**：出招中、硬直中、卡肉中按下的 A 或 B 都缓冲，只留最后一个，0.4 秒没执行就作废（沿用旧规则）。
  两处和旧版不同（代码审查后改）：卡肉的时间不算进这 0.4 秒（否则蓄力斩命中后接追斩会丢）；还按着的 B 不作废，轮到时直接起蓄力斩。
- **蓄力斩的朝向**：蓄力中可以转身，松手那一刻的朝向就是这一刀的朝向（判定、踏步都按它）。前摇结束前就松开的 B 是最小蓄力（伤害和踏步都不加）。
- **举盾时**：盾举着或排队等着举时，A 和 B 不响应。
- **副手键排队**（2026-10-01 用户决定：举盾不能打断后摇）：出招中（前摇、挥动、后摇）按下，等这一招的后摇整个放完才举盾；
  硬直中按下，硬直结束还按着就举盾。排队期间按 A、B 不响应，所以这一招不会再往下连；排队期间松开副手键就取消。
  蓄力中按副手键仍然立刻丢掉蓄力、举盾；按住 B 时在蓄力斩的前摇里按副手键，前摇一结束就丢掉蓄力、举盾。
  背后挨打时盾被打掉，硬直结束后如果副手键还按着，会自己再举起来。
- **跑步被打断**（用户 2026-10-01）：出招时站定，举盾时按 0.3 倍速慢走；两种情况跑步都立刻结束，松开后重新计 2 秒。
- **副手为空**：副手键灰掉、按下不响应（已测试）；在 M6 有装备界面之前，游戏里还没有办法卸下盾。
- **交互键**：仍然没有可交互的东西，保持半透明。
- **界面**：顶部左边是生命和格挡条（扣空锁定时变灰），中间是正在打的连段（A、B、停顿点）和招式名，右边是木桩的生命和失衡格。帧率等数字挪到了底部正中。
- **连段中转身减半**（2026-10-01 用户要求，为了平衡）：后摇里摇杆只转向，转速是平时的一半（`combo.recoveryTurnMultiplier`），
  后摇 0.3 秒大约能转 70°。选了减速而不是限制角度：转得慢一样能慢慢瞄准，规则也简单。
- **蓄力中走路**（同日用户要求）：和举盾一样分层，上半身保持蓄力姿势，下半身按走路动作迈腿。

## 13. M4 落地时补的决定（2026-10-01）

文档里没写到、按最简单的做法定下的，以后可以改：

- **入口**：菜单里加"联机对战"，进入房间界面：创建房间、加入房间、返回。
- **房间号**：4 位数字。创建的一方显示房间号，等对方加入；加入的一方用界面上的数字键盘输入
  （横屏时系统键盘会挡住大半个屏幕，所以不用输入框），电脑上也能直接打数字、退格、回车。房间号碰巧被占用时自动换一个。
- **连接**：两台手机先连 PeerJS 的免费公共信令服务器配对，之后点对点（WebRTC）直接传数据，服务器不经手游戏数据（旧版做法）。
  PeerJS 放在 `vendor/peerjs/`，不用另外下载。只配了 STUN、没有 TURN：两台手机都在运营商网络下时可能连不上，要真机试。
- **开局**：连上后两边自动进竞技场，倒计时 3 秒（屏幕中间的数字，每秒一声），然后显示"开始"。倒计时里可以先推摇杆（开局就会走），按键不出招。
- **对战中的菜单**：菜单键（或 Esc）打开"对战中"面板：继续、认输、离开对战。对局不会暂停；面板开着时按键不响应，对方照样能打你。
- **结算**：一方倒下或认输后场面继续 1.4 秒，再弹出结算：胜利 / 失败 / 平局，用时、命中、受伤、格挡、弹反、剩余生命，按钮"再来一局"和"离开"。
  一方点了再来一局，另一方的面板上显示"对方想再来一局"；两边都点了就开新的一局。
- **断线提示**：5 秒收不到对方任何消息、连接断开、对方离开或切到后台，都弹出"联机结束"面板写明原因，按钮回到野外或去训练场。
  手机切到后台（包括锁屏）会直接结束这一局并通知对方（旧版也是这样）；不做断线重连。
- **测试和调试用的地址参数**：`?link=local` 让同一个浏览器的两个标签页直接对战（不联网；电脑上自己试、浏览器测试都用它）；
  `?peer=主机:端口` 换用自己搭的 PeerServer（公共服务器不稳定时也能用它）。

## 14. M5 落地时补的决定（2026-10-02）

文档里没写到、按最简单的做法定下的，以后可以改：

  已经选中的目标要走出 1.8 格才放开，并且比别的目标优先一点，提示不会在边缘闪。目标每个模拟步重选，是模拟状态（`focus`）。

- **据点的建筑**：温泉按一下生命回满；仓库打开面板，列出带着的金币和材料；商店、铁匠铺打开面板，写"在后面的版本（M6）开放"，也列出带着的东西。面板开着时模拟停住。

- **进区域时**屏幕中间显示区域名，下面一行写"安全区"或"首领：哥布林头目"或"首领已被击败"，2 秒后淡出。

## 15. M6 落地时补的决定（2026-10-02）

文档里没写到、按最简单的做法定下的，以后可以改：

- **副手键看副手是什么**：按钮上画当前副手的图标（盾、火把、药水瓶）；拿火把时点燃后图标的火焰变亮；拿药水时右上角有剩余瓶数，喝光了按钮灰掉不响应；副手空着也灰掉。
  只有拿盾时才显示格挡条。
- **药水**：按一下就喝。出招或硬直中按下，会等这一招（或硬直）结束再喝，等的时候按 A、B 不出招，再按一次副手键取消（和盾的排队一样，只是不用一直按着）。
  喝的时候慢走（和举盾一样 0.3 倍速），A、B 不响应；被打中（不是被挡住）就洒掉这一口，瓶子不少。蓄力中按下会丢掉蓄力。
- **火把**：按一下点燃，再按一下熄灭，没有按住的用法。点燃的火把让交互键能点燃枯木丛（交互键上写"点燃"，没点燃时写"先点燃火把"，拿的不是火把时写"要用火把点燃"）。
- **背包**（仓库就是它）：菜单里的"背包"或据点仓库的门进。两个标签：
  - 装备：拥有的装备按主手、副手、护甲、饰品排开，穿着的标"穿着"；选中后右边写说明、加多少属性，以及换上（或卸下）以后生命、攻击、防御从多少变成多少；
    按钮"换上（替下 X）"或"卸下"（主手不能卸）。
  - 物品：材料和药水的数量和说明。
  在据点以外打开只能看，按钮灰掉，写"只能在据点里换装备"。关掉背包时如果换过装备，据点在原地重建一次，人物换上新的样子（位置和剩余生命不变）。
- **商店**：两个标签，"买"（药水 15 金币，最多 5 瓶；火把 30 金币，只买一次）和"卖"（带着的材料，卖一个或全部卖掉）。
- **铁匠铺**：列出能打造的装备，能马上打造的亮着、标"能打造"，已有的标"已有"；选中后列出要的金币和材料（够的绿色、不够的红色），按"打造"。打造好以后去背包换上。
- 三个界面都是横屏两栏（左边列表、右边详情），开着时游戏停住；Esc 或"关闭"关掉。每次买卖、打造、换装都立刻写存档。
- **存档**：版本 2，多了穿着的装备；拥有的装备在物品里。M5 的版本 1 存档读进来时补上开局装备。
