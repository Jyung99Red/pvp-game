## 1. 一句话

出招从两个按钮（轻击 / 重击）改成**派生树**：每一段都是**独立的一招**，有自己的前摇、生效、后摇、
倍率和动作表现；下一段出哪一招，由**轻点、长按、停顿**三种输入决定。
单角色 10+ 招是常态，这是重构，不是在现有轻击/重击上挂分支。

## 2. 参考与取舍

| 来源 | 取什么 | 不取什么 |
|---|---|---|
| 魔物猎人 | 派生树：每招只派生固定几招；出手即承诺；怪物的阶段化行为 | 体力条 |
| 街机格斗 | 每招固定的前摇 / 生效 / 后摇（帧数据），不因按得快而变快；输入缓冲 | 搓招指令、帧级精度 |
| 鬼泣 | 同一按键靠长按、停顿分出不同招（停顿连段）；续段从后摇中途接上，连段流畅；每段独立动作与倍率 | 多按键组合、空中连段 |

共同点：**分支来自"节奏与时机"，不是手速，也不是更多按钮**。
本项目只有中央键 + 防御 + 四向技能，所以分支信号只有轻点、长按、停顿三种。

## 3. 每一招的时间轴（已定）

每招分三段，以一记横扫为例：

```
按下 ── 前摇 ──── 挥动 ──── 后摇 ────────────────────┐
       举刀蓄势   刀划过扇形    │派生点│     收刀回架势
       无伤害     扫到谁打谁    续段从这里接上  不续段才放完
```

- **前摇**：按下那一刻动作就开始（举刀），所以手感是即时的；这一段没有伤害。
- **挥动**：刀从扇形一边扫到另一边。刀扫过敌人所在的角度（且在射程内）时命中，
  每招对同一目标只中一次；站在起刀一侧的先挨打。
- **后摇**：收刀回架势。后摇中途有一个**派生点**：
  - 已经输入了下一段：到派生点立刻出下一招，剩下的后摇跳过（鬼泣式的流畅连段）；
  - 没有输入：后摇完整放完，回到站定。
- 前摇、挥动、后摇、派生点**按招式写死**，不受属性和装备影响。
- 方向：前摇和挥动期间锁定；后摇期间拖动中央键**只转向、不移动**；下一段沿出招那一刻的朝向。

输入何时被接受：

- **挥动结束之前的输入直接丢弃**，不缓冲。（试玩后已改为预输入，见第 13 节。）这是防拼手速的核心：狂点不会让招变快，也抢不到下一段。
- 挥动结束（命中已结算）之后的输入**缓冲一个**，到派生点执行。
- 连段的成本在于**停下来**：不续段要吃满后摇；收尾招没有派生，后摇最长，是一套连段真正的破绽。
- 段数越靠后，动作越重、后摇越长，让玩家不看数字也知道打到第几段。

## 4. 三种输入

记 `T` = 轻点，`H` = 长按，`-` = 停顿。

| 输入 | 判定 |
|---|---|
| `T` 轻点 | 在停顿线之前按下并短按松手 |
| `H` 长按 | 按住达到阈值，松手出招 |
| `- T` 停顿后轻点 | 挥动结束后**故意不按**，让后摇放完，越过停顿线之后、窗口关闭之前再轻点 |

停顿不是蓄力：蓄力是按住不放，停顿是**什么都不按**。
`T T T` 与 `T T - T` 前两段相同，第三段是两招完全不同的招。

以挥动结束为 0 点，下一段的时间分区：

```
0 ──── 派生点 ──── 后摇结束 ──── 停顿线 ──── 窗口关闭
  缓冲→普通续段    │  普通续段  │  停顿续段  │ 回到第 1 段
```

规则：

1. **停顿线必须晚于后摇结束**，由参数保证；否则后摇里缓冲的普通输入会被误判成停顿。
2. **没有停顿派生的节点，停顿后的轻点按普通续段处理**：停顿只解锁新招，不惩罚慢一点的玩家。
3. 越过停顿线时给一个视觉提示（例如武器闪光）。
4. 停顿只接 `T`；每种武器只有 1～2 个节点带停顿派生。
5. **停顿只改变轻点**：长按不论有没有停顿，都算该节点的长按派生。
6. 到了派生点，手指还按着、尚未分出轻点还是长按：等判定出来再出招，后摇照常继续。

## 5. 派生树示例

序列长度 ≤ 3，名字与动作仅为占位：

| 序列 | 性质 |
|---|---|
| `T` | 一段：左横扫 |
| `T T` | 二段：右横扫 |
| `T T T` | 三段收尾：回旋 |
| `T T - T` | 停顿派生：连刺（与 `T T T` 是不同的招） |
| `T H` | 二段分支：中途长按，蓄力收尾 |
| `H` | 起手长按：蓄力斩 |
| `H T` | 蓄力斩后追击 |

### 长按的两种身份

- **起手的 `H`**：保留现有完整蓄力，即蓄力中可移动、转向，伤害随蓄力时长增加，"满蓄"技能照旧作用于它。
  **不再有取消圈**：松手就出招。
- **连段中间的 `H`**：只是固定阈值的开关，按够时长就升级成该节点的长按招。
  不能移动，拖动只转向；伤害不随时长变化。

## 6. 中断与取消（已定）

- 所有动作一旦开始都不能被移动、技能或下一招取消；**唯一的例外是格挡**。
- 格挡能打断**后摇**和**起手蓄力**，不能打断前摇和挥动：一旦起手，这一刀一定劈出去。
  - 后摇里命中已经结算完，直接切到举盾；PVE 与 PVP 共用同一处改动。
  - 起手蓄力还没出手，按格挡就丢掉蓄力、直接举盾。取消圈去掉后，这是放弃蓄力的唯一办法。
  - 不打断前摇和挥动：命中还没结算，撤掉攻击要连带处理动画、范围提示和 PVP 结算流程；
    设计上也会变成"出手随时反悔"。
  - 代价：收尾招的长后摇也能被格挡打断，破绽只剩举盾的代价。这是接受的取舍。
- **连段中不能移动，只能转向**：后摇里拖动中央键只改朝向。
- 连段在以下情况中断并回到第 1 段：超出窗口、受击、真正开始移动（后摇结束后仍拖着）、举盾、放技能。

## 7. 防御：格挡条（已定）

**AP 取消**，改为格挡条。格挡条只作用于防御：

| 时机 | 扣多少 |
|---|---|
| 按下格挡（举盾） | 立刻扣少量；防止反复点防御碰弹反 |
| 按住格挡期间 | 缓慢持续扣 |
| 挡下攻击 | 按承受的伤害扣 |
| 完美弹反（举盾后极短时间内挡下） | 比同一击的普通格挡扣得少 |

- **回复**：不举盾时回复，约 3 秒从 0 回满；举盾期间不回复。回复速度固定，暂不接属性。
- **锁定**：条空后，回复到约 40% 之前不能格挡，也就不能完美弹反。
- 完美弹反就是现在的"手动弹反"，判定方式不变：举盾后的弹反窗口内挨打即成功。
- 弹反**技能**（左方向，弹反护体）不变，仍然只吃 SP，与格挡条无关。

## 8. 资源

- **AP 取消**：攻击不带资源约束，连段长度由招式表和后摇决定。
- **SP 与连段无关**：SP 只服务四向技能，连段不吃 SP、也不回 SP。
- 敌人侧隐藏的 `enemyApMax / enemyApRegen` 现在实际是怪物出招频率的节流阀，见待定第 2 条。

## 9. 怪物侧（在现有基础上加魔物猎人参考，最简）

现有：巡逻 / 警觉 / 脱战，两招循环（起手-锁定-生效-后摇），连段概率，狂暴。

在此基础上：

- 招式更多，且能**派生**：怪物也有自己的连段，玩家读得出"接下来还有一下"。
- **阶段化**：怒 / 疲劳 / 濒死，同一只怪在不同阶段给出不同的应对。
- **预兆更清楚**：每招起手可读，躲避与反击有依据。

目标：玩家能读出怪物的下一步，而不是背一套固定循环。

## 10. 实现时会改动的现有规则

以下是现有代码里的规则，落地时要同步改（相关测试也要跟着改）：

- 手动弹反消耗 AP → 完美弹反消耗格挡条。
- 现在格挡扣 1 AP、手动弹反扣 0.5 AP，举盾门槛 1 AP → 换成第 7 节的三处扣条和空条锁定。
- 出招/后摇期间"保留一个最新指令"、后摇结束才执行 → 改为挥动结束前丢弃、之后缓冲一个、到派生点执行。
- 玩家攻击时序统一取自 `gameConfig.training` → 被按招式写死的时序取代。
- 命中现在在前摇结束的一刻整片判定一次 → 改为挥动期间按刀扫过的角度判定。
- 中央键拖出死区现在立刻锁定为移动，后摇中不能转向 → 连段中拖动只转向，连段结束后才移动。
- 蓄力与防御现在互斥（蓄力中按防御无效）→ 按防御丢掉蓄力、直接举盾。
- 后摇中按防御现在是排队、后摇结束才举盾 → 直接打断后摇举盾。
- 敌人硬直累积现在只认"是不是重击"（`a.heavy`）→ 每招自带硬直值。
- 设置里的"中心取消"（`controls.cancelAtCenter`）不再作用于蓄力，只剩技能使用。
- 行动力条、`getApMax` / `apMax`、`attackApCost` / `guardRequiredAp` / `blockApCost` / `parryCost` 删除或替换。
- `focus` 不再管 AP 回复，需要新作用。
- 竞技场效果 `ap_surge`（深渊领主：双方行动力恢复加速）作废，需要重做。
- PVP 规则版本号要上调。

## 11. 待定

1. **后摇转向之后怎么续段**：转向是一次拖动，续段是一次轻点，所以要"拖动转向 → 松手 → 再轻点"，
   短后摇里可能来不及。可选：
   - 保持两个手势：规则干净，"按住移动永远不会变成攻击"不受影响；
   - 后摇里拖动后松手本身算一次 `T`，朝拖动方向续段：一个手势完成瞄准加出招，但要改上面那条设计。
2. **敌人是否保留资源条**：倾向跟玩家一起取消，改成纯时序节奏（起手 / 锁定 / 生效 / 后摇 + 进攻间隔）。
   怪物的 `focus` 换算成进攻间隔，focus 越低间隔越长，保留原来"越慢越稀"的效果。
   `ap_surge` 可改成"双方后摇缩短、敌人进攻间隔缩短"。怪物侧整体之后再讨论。
3. **格挡条细节**：按格挡减伤前还是减伤后的伤害扣。
4. **疾速技能**：现在会加快蓄力速度。蓄力不是前摇，倾向保留。
5. **招式表规模**：每种武器的具体招数与分段上限。倾向先拿一种武器做 8 招左右跑通手感。

### 容易漏掉的地方

- **伤害平衡（已定：所有生命上调）**：现在 AP 把出招频率限制在每 2 秒左右一次（focus 10 时）；
  取消 AP 后可以一直连段，输出会成倍上升。先估算连段的持续输出比现在高多少倍，
  再按这个倍数上调所有生命（玩家、怪物、PVP）。
- **属性与装备（已定：暂时简化，装备随便改）**：`focus` 只保留 SP 回复；"战意戒指"
  （`ap_max_bonus`，行动力上限 +1）等与 AP 相关的装备效果可以直接改掉或换成新效果。存档里已有的装备要能正常读。
- **"深渊领主"的 `ap_surge`**：玩家没有 AP 之后，这个竞技场效果只剩对敌人生效。怪物侧讨论之前先保持现状。
- **挥动期间的命中判定**要按两次模拟步之间刀扫过的角度区间来算，不能只看当下的角度，否则快速挥动会漏判。
- **PVP**：快照要带上连段状态（当前节点、窗口计时）和格挡条，快照校验、访客预测都要认识新状态；上调 `RULE_VERSION`。
- **区域探索不出招（已定）**：拖动永远是移动。现在站着不动时轻点中央键会挥一刀（靠近建筑时是交互），
  改为探索时轻点不出招：靠近建筑是交互，其他时候什么都不做。钉住旧行为的测试
  （`a standing tap swings and recovers instead of locking the walker up`）要改写。
- **打击感（要做，分两步）**：
  1. 表现层，不影响判定：刀光拖尾、命中火花与闪白、震屏（镜头平移抖动）、音效。
     项目目前**完全没有声音**，这是打击感最大的缺口；初版可以用 Web Audio 程序合成，不需要音频素材。
     手机浏览器要在第一次触摸后才能出声。
  2. 模拟层，影响判定：卡肉（命中时攻击者和被打者的计时暂停几十毫秒）、受击后退。
     会改变时序和位置，必须放在模拟里，PVP 主机和访客才一致；要上调 `RULE_VERSION`。
- **界面**：行动力条换成格挡条；需要显示连段段数和停顿提示；设置里"中心取消"的说明改为只作用于技能；训练场最好能显示当前在派生树的哪个节点。
- **测试**：约 29 行测试代码涉及 AP，还有固定的轻/重击时序，这些都会按设计改写，属于预期改动。
- **文档**：`README.md` 的操作说明落地后要按新规则重写。
- **PVP 对刀（用户明确要求，尚未实现）**：双方的刀在同一步相交时触发对刀。挥动段有了刀的角度之后才好做；
  规则（伤害、硬直）待定。不要用"按收包时间差 100ms 判定"的旧做法。

### 训练场（已定）

与正式战斗完全同一套：同一张招式表、同一套参数、装备照常生效，数据只写一份。

**训练场并入据点，不再保留独立界面**。据点（安全区域）里放一个训练建筑，交互后与训练用的敌人开打，
走的是正式战斗的同一条流程：不发奖励、不会阵亡。
然后删掉独立的 `training.html`、`pve/training.js`、`pve/training.css` 和清单里的 `training` 条目；
`game_config.js` 里的 `training` 预设改为各模式共用的战斗基础预设。

### 落地顺序

每一步结束时游戏都能玩、测试全绿：

1. **招式表与三段时间轴**：前摇 / 挥动 / 后摇、挥动扫角命中、派生点；先只有 `T` 链。
2. **AP 换格挡条**：举盾、格挡、完美弹反扣条，空条锁定；格挡打断后摇与起手蓄力。
3. **完整输入**：连段中间的 `H`、停顿、起手 `H` 并入派生树、后摇转向、挥动结束前丢弃输入。
4. **PVP**：快照、预测、规则版本。
5. **打击感第二步**（卡肉、受击后退）。
6. **平衡、界面、训练场并入据点、文档**。

打击感第一步是纯表现，可以在第 1 步之后的任何时候单独做。

### 以后换 3D 时要守住的边界

> 2026-10-01：命中判定已定为按 3D 模型骨骼触碰，本节"模拟保持在 2D、3D 只换渲染层"的前提不再成立，以 `3d-migration-concept.md` 为准。

模拟保持在 2D 平面上，3D 只换渲染层，所以要做到"除了界面和场景都不用动"，现在开发时就要守住：

- 战斗逻辑不读任何画面数据；画面只读状态和事件（现在就是这样）。
- 每招对外提供"当前阶段 + 阶段进度（0～1）+ 刀的角度"，渲染层据此摆姿势。2D 画刀、3D 播骨骼动画都读这一份。
- 招式表里逻辑字段（时序、范围、倍率）和表现字段（动作名、拖尾）分开，3D 只需要补表现字段。
- 屏幕拖动方向换算成世界方向的地方只保留一处。3D 镜头一倾斜，这里要改成投影到地面。

即使守住这些，也有几处不是无缝的：区域测试靠 2D 绘制指令定位传送门和玩家，换渲染层时要重写；
视野遮挡（可见多边形）的阴影要在 3D 里重新做；而 3D 最大的成本是模型和动作素材，不在代码。

## 13. 实现记录（2026-09-30）

文档没写死、实现时定下的做法，试玩时重点看：

- **起手轻点松手出招**：按下那一刻还分不出轻点和长按，所以起手的 `T` 在松手时进入前摇。
- **第 8 招**：第 5 节的 7 招之外补了 `T T H` 下劈，凑够 8 招。每招单独写失衡值，取代原来"重击 +1"。
- **挥动判定**：每个模拟步把刀扫过的角度区间当作小扇形判定，快挥也不会漏；回旋斩是 360° 扇形。
- **预输入（试玩反馈改定）**：第 3 节原定"挥动结束之前的输入直接丢弃"，已改为出招中任何时候按下都缓冲，只留最后一个，到派生点执行。丢弃会让按早一点的输入（尤其长按）无声无息地没了，手感不连贯。代价是狂点也能一路连到收尾招，但招式时序写死，狂点依然不会让招变快；停顿派生仍需真的停手。
- **缓冲的清理（试玩反馈）**：狂点后想走时，残留的那一下会在后摇结束时多出一刀。现在两条规则处理：新的一次按下会替换之前缓冲的轻点/长按（以手上正在做的这一下为准，按住拖动想走时旧的那下就没了）；缓冲超过 0.4 秒仍未执行就作废（收尾招前段按的那一下不会等到后摇结束再出）。持续狂点时最后一下总是新的，连段不受影响。最初试过"拖动才清缓冲"，但它和连段长按的转向冲突，已改掉。
- **硬直中的按键**：只有前摇和挥动中的按键被丢弃；硬直中的轻点仍缓冲，硬直结束后从第 1 段出。
- **连段中间的 `H`**：以按下那一刻是否在出招过程中或连段窗口内判定，必须先按住不动 0.25 秒（先拖动的是移动，打完就跑不会误出长按招）。之后进入蓄势：只转向、不移动；松手立即出招，或蓄势满 0.25 秒自动出招（试玩反馈：既要不松手也能出，又要按住时能转向）。起手 `H` 仍是蓄力、松手出招。
- **自己的范围预警**：只在挥完时闪一次；前摇里的范围预警和挥完闪光连在一起看起来像闪两下（试玩反馈），已去掉。
- **格挡的时机**：前摇、挥动中按下的格挡，在挥动结束那一刻直接举盾；硬直中按下的等硬直结束。扣空格挡条的那一击照常算格挡，结算后再放下盾。
- **格挡条初版数值**：满条 100，举盾 10，按住 10/秒，挡下一击按减伤前伤害折算最大生命扣条，完美弹反扣一半，约 3 秒回满，空条锁到 40%。
- **装备与资源**：战意戒指改为格挡条上限 +25%；`focus` 只管 SP；敌人保留隐藏 AP；`ap_surge` 现在只加快敌人出招（提示文案已改），重做仍待怪物侧讨论。
- **生命上调取 3 倍**：实测连段持续输出约 0.62～0.77 ATK/秒；旧规则下只点轻击约 0.15，最优打法约 0.36，所以新旧比约 2～4.6 倍，取 3（`balance.hpScale`）。玩家和怪物生命同乘 3 而怪物伤害不变，战斗时长大致不变，但玩家能多挨约 3 倍的打，PVE 会明显变宽松；如果要保持原来的危险程度，可以再把怪物 ATK 也上调。
- **卡肉与后退**：命中 60ms、格挡 40ms、弹反 80ms；后退分别为 10、5、8 世界单位，0.12 秒推完。
- **PVP 规则版本**：随每个改动规则的步骤上调，现在为 15。对刀仍未实现。（2026-10-01 重建 M4 起不再手写，改为连上时自动比对规则指纹。）
- **训练场**：打测试木桩；满血开打，生命不写回存档；结束时显示命中、格挡、弹反统计。木桩固定在训练场东侧，朝一个方向定时出招，不追人、不转向、不被击退（试玩反馈）。
- **音效**：程序合成，第一次触摸后才发声，设置里可关；需要在手机上实际听一下音量和音色。
