# 3D 迁移概念笔记

**状态：概念阶段，未开工。** 2026-10-01 起草。
样机：`docs/tasks/3d-prototype.html`（2026-10-01，效果已认可；从 cdn.jsdelivr.net 加载 three.js，要联网、走 http 打开）。
写设计意图、已定规则、暂定做法和落地顺序。现行行为以代码、`game_config.js` 和
`combat-parameter-inventory.md` 为准。

本笔记取代 `combat-combo-concept.md` 第 12 节"以后换 3D 时要守住的边界"的前提：
那一节假设"模拟保持在 2D 平面上，3D 只换渲染层"。现在命中判定改为骨骼触碰，
战斗模拟本身要认识骨骼和动作，所以这次是**模拟和画面一起改**，不只是换渲染层。

## 1. 一句话

画面从 2D canvas 换成**方块风格的 3D**，素材全部从零做，用代码数据描述；
命中判定从"地面上的扇形和圆"改为"**3D 模型骨骼上的盒子相碰**"。

## 2. 已定

| 项 | 决定 |

## 3. 方块素材

### 3.1 方块风格和骨骼判定是一对

每个身体部件就是一个盒子，挂在一根骨骼上。**画出来的盒子就是判定用的盒子**，
看到的和打到的完全一致，不用另做一套碰撞体，也不会出现"模型碰到了却没算中"。

### 3.2 素材是数据，不是文件

- **骨架**：骨骼树。每根骨骼有名字、父骨骼、关节位置。
- **部件**：每根骨骼挂若干盒子（尺寸、偏移、颜色），并标明用途：
  - `body`：受击盒；
  - `weapon`：攻击盒；
  - `deco`：只画不判定（羽饰、披风之类）。
- **动作**：少量关键姿势，不是逐帧（见 3.5）。每个姿势记录几根骨骼的旋转。踏步、冲刺的前移另写成每招一个距离。
- 全部写成 JS 数据，和普通脚本一样按 `client-assets.json` 的顺序加载；Node 测试能直接读，不需要浏览器。
- 角色和装备分开组装：武器、盾是挂在手骨上的独立部件，换装备就换盒子。
  装备栏是左右手，两只手都可能拿武器或盾，挂点要两边都有。

### 3.3 初版素材清单

| 类别 | 内容 |
|---|---|
| 骨架 | 人形（约 9 根骨：底座、骨盆、躯干、头、左右肩、持武器的手腕、左右腿。四肢不分上下段，和 Minecraft 一样；样机证明够用）、四足、龙形（带尾和翼）、巨型人形 |
| 玩家 | 人形角色；武器：木剑、铁剑、刺客短刃；盾：木盾、铁盾 |
| 玩家动作 | 站立、行走、举盾、受击、硬直、蓄力姿势、连段中间的蓄势；8 招各自的前摇、挥动、后摇 |
| 怪物 | 测试木桩、哥布林、骷髅武士、暗影刺客、兽人苦工（人形）；野狼（四足）；幼龙、古龙（龙形）；岩石傀儡、深渊领主（巨型人形） |
| 场景 | 地面方块、墙、传送门、据点建筑、训练木桩 |
| 特效 | 小方块碎屑、刀光拖尾、命中闪白 |

### 3.4 预览工具

做一个开发用的预览页：选模型、选动作、拖时间轴、显示判定盒。
没有它，调动作只能进游戏打一遍看，效率太低。预览页不进游戏清单。

### 3.5 动作怎么做

- **不是逐帧调**。每招只写几个关键姿势，中间每一帧由程序按缓动插值算出来。
- 样机的做法：每招 2 个关键姿势（前摇结束、挥动结束），后摇回到共用的站姿。
  8 招一共 16 个姿势、154 个数字。正式版每招 3～4 个姿势（加蓄势、收招的回弹），手感会更好。
- 待机呼吸、走路摆腿、受击后仰、失衡摇晃、尾巴摆动都用公式（正弦波）生成，不需要关键姿势。
- 降低工作量的办法：
  - 同一副骨架多只怪共用：哥布林、骷髅武士、兽人苦工、暗影刺客都是人形；幼龙和古龙共用龙形。
  - 常用姿势做成姿势库（举过头顶、拖刀在后……），不同的招拿来组合；左右对称的招镜像生成。
  - 四肢不分上下段，每个姿势要调的骨头少。
- 贴图分辨率不影响工作量：贴图全由代码生成，所有贴图加起来约 70 行。16×16 还是 12×12 只是画风选择。

## 4. 骨骼判定

### 4.1 怎么判

- 每个模拟步，用正向运动学（沿骨骼树按关键帧累乘变换）算出攻击方武器盒和受击方身体盒在世界中的位置和朝向。
- 两个有向盒子相交即命中。每招对同一目标只中一次（保留现规则）。
- **只有挥动段的武器盒算命中**。前摇、后摇里武器碰到人不算。
- **要防穿透**：模拟步是 0.01 秒，回旋斩挥动 0.18 秒转 360°，每步约转 20°，
  刀尖一步走约 27 单位，比玩家身体（半径 12）还宽。所以两步之间要插值几次再测（子步），
  子步数按刀尖移动距离定，保证每个子步移动不超过最薄受击盒的一半。
  现在的扇形判定也按"两步之间刀扫过的角度"算，是同一个问题。

### 4.2 时长仍由招式表决定

- 前摇、挥动、后摇、派生点的时长仍写在 `game_config.js` 的 `combo.moves`。
- 动作关键帧按"**阶段内进度 0～1**"写，播放时拉伸到招式表的时长。
- 这样预输入、派生点、停顿线、PVP 校验都不用改，调时长也不用改动作。
- 现有的 `pose()`（`pve/spatial_engine.js`）已经提供"阶段 + 进度"，正好作为取样输入；
  它返回的 `blade` 角度由骨骼取代。
- PVP 快照不用带骨骼数据：骨骼姿势由"招式 + 阶段 + 进度 + 位置 + 朝向"推出，
  快照里本来就有这些，主机和访客各自算。

### 4.3 招式表的变化

- `range`、`arc`、`sweep` 不再用于判定，射程由动作和武器长度决定。
- 但仍需要"大概射程"：AI 判断何时出手（`attackDistance`）、自动朝向、范围预警。
  由加载时扫一遍动作算出（武器盒在挥动段扫过的地面投影），不手写。
- **武器长度不同，射程自然不同**：短刃短、铁剑长。这是"武器之间的差异"的第一步，不用另做招式表。
- **射程由动作决定**：样机里下劈、上挑起初一直打不中，因为刀从右肩直上直下挥，从目标身边擦了过去；
  把手臂往中线收一点才命中。所以每招都要有自动测试：标准距离、标准体型的目标必须被打中。
  以后调平衡，很多时候调的是动作，不只是数字。
- 蓄力斩现在的射程和扇形随蓄力增大（`minRange`→`range`、`minArc`→`arc`），骨骼判定下要换个方式体现（待定第 5 条）。
- 影响判定的尺寸（武器长度、身体盒大小、角色比例）是可调数值，放 `game_config.js`，
  同步参数清单；姿势关键帧是素材，放素材数据文件。

### 4.4 怪物

- 怪物招式同样换成动作加骨骼判定，`sector`、`circle`、`dash` 不再用于判定。
- 冲刺：身体盒本身作攻击盒（撞击），沿路径按子步测。
- **范围预警**（地上的红区）从动作预先算出：挥动段攻击盒扫过的地面投影，取外包，宁大勿小。
  红区只是提示，判定以盒子为准。
- 大型怪有多个受击盒（头、身、尾）。暂不做部位伤害倍率，但以后要做部位判定时不用改判定方式。
- 这部分要和"怪物系统调整"合并：怪物的新招式直接按骨骼动作做，不先按扇形做一遍。

## 5. 连段只有 H 造成击退和硬直（已定）

**规则**：连段里 `T` 招命中只扣血，不击退、不造成硬直、不累积失衡；
只有 `H` 招（起手蓄力斩、连段中间的长按招）才有。

| 招式 | 输入 | 现在失衡值 | 改后 |
|---|---|---|---|
| 横扫 | `T` | 0 | 0，不击退 |
| 回扫 | `T T` | 0 | 0，不击退 |
| 回旋斩 | `T T T` | 1 | 0，不击退 |
| 连刺 | `T T - T` | 1 | 0，不击退 |
| 追斩 | `H T` | 0.5 | 0，不击退 |
| 上挑 | `T H` | 1.5 | 保留，击退 |
| 下劈 | `T T H` | 1.5 | 保留，击退 |
| 蓄力斩 | `H` | 1 | 保留，击退 |

- 现在每次命中都把对方推开 10 单位（`impact.knockback.hit`）。改为每招自带击退距离，`T` 招为 0。
- **卡肉照旧对所有命中生效**（暂定）：那是打击感，不属于击退硬直。
- **PVE**：怪物本来就不吃受击硬直，只累积失衡。改后只有 `H` 招和完美弹反能打出失衡（失衡阈值 3：下劈两下即可）。
- **PVP**：现在任何命中都让对方进入 0.35 秒受击硬直并打断连段。
  改后 `T` 命中不打断对方，双方可以互换轻击，只有 `H` 能打断。这是 PVP 节奏的大改动，要试玩确认（待定第 6 条）。
- 不受影响：格挡、弹反造成的击退；怪物打玩家。
- 这条和 3D 无关，可以先单独做。

## 6. 高度：会不会很复杂

骨骼判定本来就是 3D 的，所以**判定这边几乎不增加成本**。成本在移动、AI 和镜头：

| 部分 | 跳跃 | 地形高度差 |
|---|---|---|
| 命中判定 | 不增加（盒子本来就有高度） | 不增加 |
| 移动与碰撞 | 竖直速度、重力、落地，中等 | 地面高度查询；台阶能走上去，落差太大当墙，中等 |
| 战斗规则 | 空中能做什么（出招？举盾？）、落地硬直，要设计 | 基本不用 |
| 怪物 AI | 要判断能不能跳过地面攻击 | 追人要绕路，需要寻路，**最贵** |
| 视线遮挡 | 不变 | 矮台阶不挡视线、高的挡，可见区域要改算法 |
| 镜头 | 不变 | 角色走到高方块后面会被挡，要做遮挡透明 |
| PVP | 快照加高度和竖直速度 | 同左 |

结论：**跳跃中等，地形高度差偏大**，贵在寻路和镜头遮挡，不在判定。
只要现在守住下面几条，以后加高度是往上加，不是重写：

- 位置从一开始就带高度坐标，现在恒为 0。
- 判定全程用 3D 盒子，不投影回地面。
- 所有"地面在哪"的地方走同一个查询函数，现在恒返回 0。
- 墙用带高度的方块描述（方块风格本来就是这样）。
- 现在不做：寻路、空中招式。等真要加高度时再做。

**什么时候要决定**（2026-10-01 仍在犹豫）：预留几乎不花成本，所以先预留。
跳跃在预留做好之后随时能加；地形高度差最好在第 11 节第 5 步（场景）开工前决定，因为地图要按有没有高低差来设计。

## 7. 镜头与操作（暂定）

- **固定斜视角**（俯角约 50～60°），不转镜头。触屏布局（中央键、左侧防御、右侧技能）不变。
- 屏幕拖动方向换算成世界方向只在 `ui/combat_input.js` 一处，改成按镜头朝向换算到地面。
- 视野遮挡：现在用 2D 可见多边形给看不到的地方压暗。3D 里改成地面压暗，墙后的敌人不画。
- 界面（血条、格挡条、技能盘、伤害数字、连段提示）仍是 HTML 和 2D，叠在 3D 画面上。

## 8. 渲染器：three.js（已定）

- three.js 建在 WebGL 上，性能上限相同。手机上的瓶颈是绘制调用次数和像素量，两种做法一样。
  用实例化网格把同类盒子一次画完，开销和手写差不多；阴影、雾、材质、调试辅助都是现成的。
- **接法（方案 B）**：最新版模块文件放进仓库（压缩后约 650KB，离线可用），
  `core/client_boot.js` 先用 `import()` 加载并挂到全局，再按清单加载其他脚本。
  启动器改十几行，清单加一类条目，`AGENTS.md` 的"无模块"补一句例外。
  （不选锁在 r159 的全局脚本版：版本停在 2023 年底，官方附加组件要自己改写。）
- **three.js 只负责画**：骨骼、正向运动学、盒子相交是自己写的纯 JS，放 `core/`，Node 测试和 PVP 主机都靠它；
  不用 three.js 自带的骨骼动画。每帧把算好的盒子位置写进实例化网格。
- 光照按样机：半球天光加一盏太阳平行光，阴影贴图手机上 1024、电脑上 2048；高分屏像素比上限 2。
  火把、熔岩之类的点光源不带阴影，开销很小。
- 样机的规模参考：整个场景约 81 次绘制调用、1.9 万个三角形（角色每个部件单独一个网格，正式版合并后更少）。

## 9. 现有代码要动的地方

- **新增**：骨骼、正向运动学、有向盒相交（纯数学，放 `core/`）；素材数据（骨架、部件、动作）；3D 渲染器；预览页。
- `pve/spatial_engine.js`：玩家挥刀判定（`resolveSwing` 里的 `S.contains`）和怪物出招判定（`enemyHit` 的扇形、圆、冲刺）换成盒子相交；击退按招式取值。
- `pvp/spatial_duel.js`：`judge()` 同样换成盒子相交；PVP 受击硬直只给 `H` 招；上调 `RULE_VERSION`。
- `ui/ui_spatial_battle.js`、`pve/adventure_world.js` 的 2D 绘制、`ui/fx.js` 的特效：换成 3D。
- `game_config.js`：`combo.moves` 的 `range`/`arc`/`sweep` 删除或只留给预警；`enemyMoves` 的几何改为引用动作；
  新增角色比例、武器长度、每招击退。同步 `combat-parameter-inventory.md`。
- 测试：区域测试现在靠 2D 绘制指令里玩家的圆来反推位置，要改成读模拟状态；
  断言扇形几何（射程、角度）的测试按骨骼判定改写。属于预期改动。
- 存档：装备 ID 不变，物品配置里加模型引用。
- 新目录（如果素材单独放一个目录）要同步 `AGENTS.md` 的目录说明和 `client-assets.json`。

## 11. 落地顺序

每一步结束时游戏都能玩、测试全绿：

0. **只有 `H` 击退硬直**（第 5 节）：与 3D 无关，可以先做。
1. **骨骼与判定的数学**：先按第 12 节把地基定死。骨骼树、正向运动学、有向盒相交、子步；主角骨架加一把剑和 8 招的动作；预览页。
   纯数据加 Node 测试，包括"每招在标准距离必中"。样机里的模型、姿势、盒子相交可以直接搬过来改成数据格式。
2. **训练场先换 3D**：three.js 放进仓库，启动器接上；玩家和木桩用 3D 画，判定仍用旧的扇形。
   对照两者，确认动作和射程对得上。样机里的贴图、方块、粒子、刀光代码可以沿用。
3. **玩家招式改骨骼判定**：PVE 和 PVP 共用引擎，一起改；范围预警和 AI 射程由动作算出；上调 `RULE_VERSION`。
4. **怪物**：各骨架和动作，怪物招式改骨骼判定。和"怪物系统调整"合并做。
5. **场景**：区域、据点方块化；视野遮挡；区域测试改写。
6. **收尾**：删掉 2D 绘制；更新参数清单、`README.md`。

### 和其他工作的顺序

- 判定改成骨骼触碰后，怪物的新招式应直接按骨骼动作做，所以**第 1～3 步要排在怪物招式之前**。
- 怪物 AI 那一层（去掉隐藏 AP、选招、派生连段、阶段）不依赖判定方式，可以随时做。
- 装备数值放在怪物之后（理由不变：要对着怪物的数值调）。

## 12. 地基：第 1 步就要定死的

光照、贴图这些以后改很容易；下面这些一旦铺开（模型、动作、地图都建在上面），再改就要大面积返工，所以第 1 步就定死。

### 12.1 以后难改的

| 项 | 定为 | 以后再改的代价 |
|---|---|---|
| 尺度 | **1 格 = 40 世界单位**。模拟继续用现在的世界单位，现有射程、速度、地图尺寸都不用换算。依据：玩家半径 12 = 0.3 格（Minecraft 玩家宽 0.6 格）；横扫射程 69 ≈ 1.7 格，和样机实测的臂展一致；移速 115 = 每秒 2.9 格；最大的区域 2400×1600 = 60×40 格。角色高约 1.9 格 | 所有模型、动作、射程、地图重来 |
| 坐标约定 | 3D 坐标 = (x, 高度, y)，不翻转；屏幕上方是 -z。模拟朝向 θ 换算成模型的绕竖轴旋转 = π/2 - θ（模型正面朝自身 +z）。换算只写在一处 | 写错了模型会左右镜像，到处打补丁 |
| 判定层和表现层分开 | 影响判定的姿势必须是模拟状态的纯函数（招式、阶段、进度、移动距离……）。呼吸、东张西望、披风飘动只画不判定。正向运动学在 `core/`，不依赖 three.js | 混在一起之后 PVP 主机和访客会算出不同结果，很难查 |
| 动作数据格式 | **稀疏姿势**：没写的骨头就是静止姿势；按阶段进度 0～1 写；骨骼按名字引用 | 有了它，以后加骨头、改时长都不用动旧动作；没有它，每次都要改全部动作 |
| 主角骨架 | 主角带手肘和膝盖（约 15 根骨），走路、蹲低、挥剑才生动；挂点：左右手、背、腰、头。怪物仍用四肢不分段的简单骨架 | 骨架定了以后再拆部件，要改模型和受击盒 |
| 动画系统结构 | 分层（下半身走路，上半身举盾或出招）；状态切换时交叉淡化约 0.1 秒；程序叠加层（呼吸、转身倾斜、看向目标）；根位移 | 事后补分层等于重写动画系统 |
| 地形数据格式 | 方块网格，每格记方块类型和高度（现在只有地面和墙）；角色位置连续，不对齐网格。现有墙矩形要对齐到格子，PVP 竞技场布局版本要升 | 格式不带高度，以后加高低差就得改所有地图 |
| 调色板 | 模型里写颜色名（皮肤、外衣、钢、木），不写死色值 | 写死的话，换一次画风要逐个改模型 |
| 镜头俯角 | 固定斜视角约 45～60°。模型细节要从这个角度看得清：头顶、肩甲比脸更常被看到 | 俯角大改，模型的重点细节要重做 |

### 12.2 以后改很容易的

光照和光源、贴图分辨率和画法、颜色（有调色板）、招式时长、粒子和刀光、镜头距离、加新招式、加骨头（有稀疏格式）、音效。

### 12.3 招式时长以后再调

不用提前定。动作按阶段进度写，时长在 `game_config.js`，改一个数字动作自动拉伸。要注意的只有：

- 时长改很多（例如挥动从 0.08 秒变成 0.3 秒），动作会显得飘，可能要顺手调缓动或加一个姿势。
- 挥动变快时，子步数按刀尖速度自动增加，不会漏判。
- 改了时长，PVP 要上调 `RULE_VERSION`（现在也是这样）。

## 13. 主角动作（用户偏好：生动完整）

动画系统（12.1）做好之后，下面这些随时能加，互不影响：

| 类别 | 内容 | 做法 |
|---|---|---|
| 移动 | 待机、走、跑（按速度混合，步幅跟速度匹配，不滑步）、起步前倾、急停、转身倾斜 | 走、跑循环各 2 个姿势，另一条腿镜像；倾斜用公式 |
| 战斗姿态 | 探索时剑挂在背上，进入战斗拔剑、结束收剑；举盾走；蓄力站姿；连段中的蓄势 | 拔剑、收剑各 2～3 个姿势；举盾走 = 上半身举盾加下半身走路 |
| 招式 | 8 招，每招 3～4 个姿势 | 见 3.5 |
| 受击 | 按方向后仰、硬直、格挡被推开、弹反成功、格挡条空了踉跄、倒下和复活 | 每个 2～3 个姿势 |
| 据点行为 | 泡温泉、打铁、逛商店、翻仓库、木桩前热身；站久了的小动作（伸懒腰、看四周） | 每个 2～4 个姿势循环；只画不判定 |
