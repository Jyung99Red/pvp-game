# 重建执行计划

**状态：M1～M4 已完成（2026-10-01），等真机试用意见后开始 M5。** 2026-10-01 起草。

整个游戏在同一个仓库里重建：方块风格 3D、横屏、5 个按钮、骨骼判定，不考虑旧存档。
这份文档只管**做的顺序和每一步做到什么程度**；做什么、为什么，以两份设计文档为准：

- `docs/tasks/3d-migration-concept.md`：画面、素材、骨骼判定、尺度和坐标、主角动作、装备模型。
- `docs/tasks/controls-landscape-concept.md`：横屏、移动摇杆、A 和 B、副手键、交互键、放弃技能。

- `docs/tasks/combat-combo-concept.md`：招式表、时间轴、派生树、格挡条规则（输入层除外）。

两份设计文档里的"落地顺序"一节是按"在旧代码上逐步改"写的，已被本计划取代。

## 2. 里程碑

每个里程碑结束时：`node --test "tests/*.test.cjs"` 全绿；在浏览器里能打开并玩到这一步的内容；
提交并推送；告诉用户要在手机上试什么。用户试完、提出意见后，再开始下一个。
能自己验证的部分要自己验证（办法见第 5 节），汇报时写清做了什么、结果如何；验证不了的单独列出，写成"请在手机上试：……"。

## 3. 能不能一次做完

不能，也不该。这是 6 个里程碑，M5 可能还要拆成两次，大概 6～8 次会话。原因：

- 每个里程碑最后都要在**真机上试**（摇杆、按钮、连段手感、帧率），这些自动测试代替不了。
  下一步建在上一步之上，手感有问题要先改，不然越往后越难改。
- 一次会话的上下文有限，一次做太多，前面的细节容易丢。每个里程碑大小合适，做完提交，下一次会话从文档和代码重新开始，最稳。

## 5. 新会话自己能测什么

2026-10-01 在这个云端容器里实测过：预装了 Chromium 和 Playwright（全局安装在 `/opt/node22/lib/node_modules/playwright`），
无头模式下 WebGL 用软件渲染（SwiftShader）能跑，能截图，能模拟横屏手机和两根手指。

**写浏览器测试的办法**（已验证可用）：

- 启动：`chromium.launch({ args: ['--use-gl=angle', '--use-angle=swiftshader', '--enable-unsafe-swiftshader'] })`。
- 横屏手机：`browser.newContext({ viewport: { width: 844, height: 390 }, hasTouch: true, isMobile: true, deviceScaleFactor: 2 })`。
- 两根拇指：`page.touchscreen.tap` 只能单点；多点触控要开 CDP 会话，用 `Input.dispatchTouchEvent`，
  两个触点会得到不同的 `pointerId`。
- 看画面：截图存成 PNG，用 Read 工具打开，可以检查画面、按钮布局、文字有没有被裁掉。
- 外部地址（`cdn.jsdelivr.net`、字体）在这个环境里连不上，但 npm 能用：three.js 用 `npm pack three@<版本>` 取回再放进仓库
  （M1 本来就要这样做，页面也因此能离线运行）。样机从 CDN 加载 three.js，要跑它得用 `page.route` 拦截请求、拿 npm 取回的文件回应。

**能自己测**：

| 内容 | 怎么测 |
|---|---|
| 模拟规则：连段时序、派生、预输入、停顿线、格挡条、卡肉、失衡 | Node 测试，直接驱动模拟 |
| 判定：每招必中、挥动扫过的角度、矮个子怪能被打到 | Node 测试 |
| 骨骼数学、盒子相交 | Node 测试 |
| 页面能加载、没有控制台报错、资源清单完整 | 浏览器测试，收集控制台错误 |
| 画面是否正常 | 截图后自己看 |
| 横屏布局、按钮不重叠、竖屏提示出现、安全区 | 改视口尺寸，截图并检查元素位置 |
| 两根拇指同时操作（摇杆加 A、摇杆加副手键） | CDP 多点触控，检查引擎状态 |
| PVP 判定和同步逻辑 | Node 测试里主机和访客各跑一份（`tests/duel.test.cjs`） |

**测不了，要用户在手机上试**：

| 内容 | 原因 |
|---|---|
| 手感：按钮位置、大小、拇指够不够得着、连段节奏 | 要真手指 |
| 真实帧率 | 软件渲染下，样机场景只有约 3 帧每秒，数字没有参考价值；能比较的只有绘制调用次数和三角形数量 |
| iPhone 的行为：方向锁定、全屏、安全区 | 容器里只有 Chromium，没有 Safari |
| 音效的音量和音色 | 听不到 |
| 两台设备真实联机（延迟、穿透） | 只有一个容器，出网受限，连不上公共信令服务器；能测的是协议逻辑和同一台机器上两个页面之间的 WebRTC（见下文"两台设备的对战怎么测"） |

**写测试时要注意**：

- 不要依赖真实时间。软件渲染下页面只有几帧每秒，所以测试里用确定性的步进函数推进模拟
  （样机里的 `__proto.run(seconds)` 就是这个做法），渲染循环里对每帧时间设上限，避免一帧跳太多。
  确实要测实时循环时，等"已经跑过几帧"或等结果出现，不要只等固定时间：2026-10-01 实测无头模式下两帧之间有时隔 0.5～0.75 秒，
  冒烟测试只等 0.6 秒时偶尔一帧都没跑到（M3 收尾时修掉）。
- 模拟和判定放在不依赖浏览器的 `core/` 里，才能用 Node 快速、确定地测。

**M1 留下的测试工具**（2026-10-01）：

- `tests/browser-smoke.test.cjs` 就是上面这套办法：横屏加载无报错、读像素确认画出了草地、按钮不重叠、竖屏提示、
  CDP 两指同时按摇杆和 A、键盘。找不到 Playwright 时自动跳过，所以 `node --test "tests/*.test.cjs"` 在哪都能跑。
  设 `SMOKE_SHOTS=<目录>` 会把截图存下来。
- 在用户的 Windows 电脑上：没有全局 Playwright，也不用下载它的浏览器。把 `playwright-core` 装在任意目录，
  设 `PLAYWRIGHT_MODULE=<该目录>/node_modules/playwright-core` 和 `PLAYWRIGHT_CHANNEL=chrome`，就用本机的 Chrome 跑。
- 页面上 `window.game`：`game.pause()` 停掉实时时钟，`game.run(秒)` 确定地推进模拟，`game.sim` 是模拟状态。
  M3 起还有 `game.load('field' | 'clearing')` 换图、`game.map` 当前图、`game.panel` 当前打开的面板（`menu`、`win`、`lose` 或 null）。
  页面默认进野外，测训练木桩的冒烟测试用 `?map=clearing` 打开。
- M4 起 `game.duel` 是对战的会话（`phase`、`selfId`、`battle`……），`game.room` 是房间界面；对战时 `game.map` 是 `'arena'`，`game.sim` 是对战的模拟。
  对战页面不要 `game.pause()`：对局靠真实时间推进，暂停只管 PVE。
- **两台设备的对战怎么测**（2026-10-01 实测可用）：
  - 浏览器测试：同一个 `BrowserContext` 里开两个页面，地址都带 `?link=local`（BroadcastChannel，不联网），从界面创建房间、按数字键盘加入，一直打到结算。
    `tests/browser-smoke.test.cjs` 就是这样做的。
  - 真的 PeerJS 加 WebRTC：容器连不上公共信令服务器 `0.peerjs.com`，但 npm 能用。在临时目录 `npm install peer`，
    起一个 `PeerServer({ port, host: '127.0.0.1', path: '/' })`（容器不支持 IPv6，要写 host），两个页面放在**不同的** `BrowserContext` 里，
    地址带 `?peer=127.0.0.1:<端口>`。无头 Chromium 两个页面之间的 WebRTC 数据通道能直接连上（不用额外参数）。
    这一步没放进自动测试（要装 npm 包），改了 `net/link.js` 时手动跑一遍。
  - 两端的协议逻辑在 `tests/duel.test.cjs` 里用内存通道测，可以加固定延迟。
- 想看模型近景时：在页面里先 `game.view.render(game.sim, 0)`，再把 `game.view.render` 临时换成空函数，
  自己摆 `game.view.camera` 并 `game.view.renderer.render(game.view.scene, game.view.camera)`（实时循环就不会盖掉这一帧）。
- three.js 的取法：`npm pack three@<版本>` 后用 esbuild 把 `build/three.module.js` 打成一个压缩文件
  （`npx esbuild <入口> --bundle --minify --format=esm`），放进 `vendor/three/`。
