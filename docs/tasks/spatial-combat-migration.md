# 任务：将走位训练场迁移为正式 PVE 战斗基础

状态：2026-09-09 M1～M4 代码已实施，正式地下城默认使用空间战斗；真机与双设备PVP验收项仍保留未勾选。
编写日期：2026-09-09。
起点：用户已试玩并反馈「能运行，操作没问题」。这确认了原型操作可用，不代表全部战斗数值和迁移方案已经定案。

## 1. 目标与完成后的体验

保留直屏、双按钮、无翻滚的操作，将已经验证的移动／攻击／防御玩法整理成可维护的战斗基础，随后接入正式地下城流程。

最终玩家从基地进入地下城，使用位置、朝向和局部攻击范围与怪物战斗；胜利后可以继续或回城，装备、角色成长、掉落、金币和检查点按明确的兼容规则工作。训练场继续存在，作为固定属性的练习和回归入口。

实施分为两个交付：

- **交付 A：训练场结构重构。** 操作、数值和当前可见行为保持一致；训练场不再是一套难以复用的独立实现。
- **交付 B：正式 PVE 接入。** 训练场与地下城使用同一个空间战斗引擎，通过配置、角色档案和外层流程区分。

本轮不扩展 PVP，不移植其网络协议，不增加翻滚、障碍物、寻路、局内三选一或新经济系统。不更换框架、不引入打包器，继续使用有序的全局 `<script>`。

## 2. 操作基线：迁移时必须保留

| 输入／状态 | 行为约定 |
|---|---|
| 操作区短按、在死区内松手 | 原地轻攻击；不能按旧规则变成 1 点惩罚伤害 |
| 长按门槛之前拖出死区 | 立即进入移动；不增加额外等待窗口 |
| 已进入移动 | 持续多久都不会蓄力；松手只停止，重新按下才能攻击 |
| 在起始触点附近长按 | 进入原地蓄力；蓄力从最初按下开始计算 |
| 蓄力达到上限 | 保持蓄力，不自动出手 |
| 蓄力后向屏幕上方划出并松手 | 重攻击；攻击朝向由角色决定，而非屏幕上方 |
| 蓄力后原地松手 | 取消，不出刀、不移动、不耗 AP |
| 蓄力后向侧方／下方松手，或上划后滑回起点松手 | 保留原型的取消行为，不转成移动 |
| 按住防御 | 原地举盾；拖动调整朝向；松手撤防 |
| 防御时转向 | 不能刷新精准防御时间窗 |
| 移动中开始防御 | 防御优先，停止移动；撤防后须重新按下移动，避免旧触摸突然恢复 |
| 蓄力、出手、收招中按防御 | 保留当前不能直接切防御的限制；蓄力需先取消 |
| 触摸取消、失去捕获、切后台 | 不得把取消误判成攻击；释放所有输入，暂停后明确点击继续 |

当前手势参数作为交付 A 的回归基线：死区 12 CSS px、长按识别 240ms、重击上划距离 32 CSS px、向上 90° 手势范围。它们属于输入配置，不随装备或角色等级改变。

## 3. 当前代码与重构动机

| 文件 | 当前职责与需要处理的边界 |
|---|---|
| `training.html`、`pve/training.css` | 独立训练页和直屏布局；应继续提供练习入口 |
| `core/spatial_combat.js` | 几何、转向、边界和圆形碰撞；已有独立函数，可直接保留 |
| `pve/training_logic.js` | 手势判定、固定数值、双方状态推进、AI、伤害、提示和绘制特效数据混在一起 |
| `pve/training.js` | Pointer Events、指针捕获、暂停、Canvas、HUD、开局／结束界面混在一起 |
| `pve/pve_logic.js` | 同时负责旧战斗循环和地下城生命周期；应保留楼层／奖励流程，逐步替换战斗实现 |
| `core/combat_resolver.js` | 目前仍被旧 PVE 和 PVP 使用，不能为训练场直接改写全局规则 |

| `tests/training.test.cjs` | 当前 11 项回归测试；重构时迁移测试入口，保留行为断言 |

原型中玩家伤害为轻击 18、重击 28～58，玩家／敌人 HP 为 120／360，没有读取装备防御或等级。不能把这些固定数值直接替换正式成长系统。

## 4. 建议的目标边界

以下文件名为实施建议，可以结合实际合并小文件；职责边界和单一实现比文件数量重要。

| 组件 | 建议位置 | 职责 |
|---|---|---|
| 空间计算 | `core/spatial_combat.js` | 圆形／扇形相交、朝向、移动边界；无 DOM、存档和全局游戏状态写入 |
| 手势识别 | `core/combat_gestures.js` | 识别 pending／move／charge／cancel，输出语义命令；可脱离浏览器测试 |
| 输入适配 | `ui/combat_input.js` | Pointer Events、pointerId、capture 和取消；不负责伤害、AP或角色状态裁决 |
| 空间战斗引擎 | `pve/spatial_engine.js` | 接收角色档案、动作配置、命令和时间步，推进战斗实例，返回事件；不依赖页面或 `state` |
| 动作与场地数据 | `pve/spatial_data.js` | 玩家动作、怪物招式、训练场预设；数值与算法分离 |
| 角色档案适配 | `pve/pve_profiles.js` | 把 `player` getter 和敌人配置转换为新引擎参数；不从引擎反向读取存档 |
| 战场视图 | `ui/ui_spatial_battle.js` | Canvas、HUD、范围提示；读取战斗快照／事件，不修改战斗状态 |
| 训练场入口 | `pve/training.js` | 固定预设、开始／暂停／重试，组合输入、引擎和视图 |
| 地下城入口 | `pve/pve_logic.js`、`pve/ui_pve.js` | 楼层、奖励、技能适配、结果界面、回城；组合同一套输入、引擎和视图 |

数据流：Pointer Events → 手势识别 → 命令 → 战斗引擎 → 状态／事件 → 视图或地下城结算。

引擎必须再次验证命令是否允许：例如输入层请求重击，引擎仍要检查蓄力状态和 AP。暂停、受击和结束会使未释放的触摸失效，不能只清空其中一层。

只建立本次需要的接口：创建、派发命令、推进、暂停／取消、读取状态和事件。事件至少覆盖攻击命中／挥空、格挡／弹反、失衡、HP变化和战斗结束；文案、颜色和动画由外层映射，不把通用事件总线作为前置工程。

## 5. 战斗与数据约定

### 5.1 空间与动作

- 世界坐标独立于 CSS 像素；保留训练场 360×400 的基线，缩放屏幕不改变距离、速度或攻击判定。
- 角色包含位置、朝向和碰撞半径。校验贴边、贴身、拐角时不能互相穿透或把防御中的角色推出去。
- 每个动作显式配置形状、范围、扇形角度、起手、锁定时机、生效、后摇和伤害参数。
- 伤害倍率不再用于间接拉长蓄力时间；不能用旧 `dmgMult` 自动生成所有新招式。
- 怪物先追踪，再承诺方向，然后出招和收招；一次动作对同一目标最多结算一次。
- 普通命中不默认打断所有怪物动作。失衡和可打断阶段显式配置，先保留训练怪的重击 +2、弹反 +1、3 点触发 1.5s 失衡基线。
- 不自动把旧 `clash` 规则接到新引擎；空间拼刀需要另行定义相交、时间与结算语义。

### 5.2 时间、随机与结束

- 新引擎统一使用秒和单调模拟时间；不得在内部读取 `Date.now()` 决定蓄力、弹反或 AI 阶段。
- `arenaEffects.tick` 目前使用毫秒，必须在单一适配点转换；效果计时随该场战斗暂停。
- 交付 A 先保留原型推进方式，不同时重做帧率策略。正式接入时校验 30／60／120 FPS；必要时使用有上限的固定子步推进，不能切后台后补算一整段攻击。
- 需要随机的掉落／暴击／AI用可注入随机源，便于复现；不要把随机算法修改混进结构提取。
- 原型当前先更新玩家，玩家致命命中会先结束，尚未执行的怪物攻击不会再发生；交付 A 保留并测试这一点。
- 正式 PVE 原有规则是结算中双方同时死亡时败北优先。交付 B 必须明确同一时间步的事件顺序和终局优先级，不因更新顺序暗中改变规则。见第 8 节审阅项。
- `battleId` 与已结算标志防止重复奖励；结束后拒绝旧输入、旧事件和继续伤害。

### 5.3 成长与装备接入清单

| 原有数据／效果 | 迁移要求 |
|---|---|
| 等级、maxHp、atk、def、强化 | 通过角色档案生效；训练场继续固定预设。正式伤害公式另列映射，不使用固定 18／58 代替角色攻击 |
| spd | 首轮保留其 AP 恢复定位，不直接同时放大走速和怪物转向速度 |
| int、`parry_window_ms` | 接入精准防御时间窗；边界须有限且非负 |
| `charge_threshold_ms` | 与 240ms 手势长按识别分离。其对重击收益／蓄力曲线的映射须审阅后确定，不能让换武器改变点按和拖动识别 |
| `guard_damage_reduce` | 明确与新格挡基础倍率如何组合；原型基础受伤 25%，旧核心为 40% 再乘装备效果，不能混用 |
| luck、`crit_chance` | 在新伤害流程中实现并显示，或在兼容清单里显式列为未接入；不能装备说明有效而实际失效 |
| `guard_thorns`、`ap_max_bonus` | 接入反伤与 AP 上限，并测试反伤致死、双方死亡和 AP 不越界 |
| 双手装备的时序选择 | 先保留现有槽位顺序取值；不要顺带改变配装规则 |

每项效果给出“已接入／需决定／不适用于本模式”的清单。正式替换前，不得留下会误导玩家的静默失效装备。

## 6. 地下城、HP 与旧技能的接入

### 6.1 继续使用现有进度与结算

- 保留绝对楼层池、Boss 轮换、检查点推进、经验、材料和 runGold 归属规则。
- 保留战斗逃跑／层间回城的现有经济规则；撤离惩罚和选层属于另外的设计任务。
- 继续下一层只重置单场位置、AI和临时动作状态；HP及已经定义为跨层保留的技能点按原规则携带。
- 战斗结束、回城、重进、重复点击都只结算一次。不能把“胜利时获得材料”和“回城时存入金币”合成重复发奖。
- 训练场始终不读写养成存档。正式战斗的瞬时位置、触摸和动作不保存，刷新继续沿用回到基地的现有模式。

### 6.2 单一 HP 写入源

建议战斗期间由战斗实例统一处理伤害、回血和上限裁剪，外层在受伤／治疗／结束时同步 `state.player.currentHp`，保证当前存档策略可继续工作。

`tick.js` 在正式空间战斗中不得直接改另一份 HP 再让引擎逐帧覆盖回来。基地仍沿用原回血；战斗中被动／温泉回血按现有频率转换为战斗治疗，受战斗暂停与结束约束。等待楼层选择时的回血应显式保留原规则，不能在此次重构里顺手重平衡。

实现前定义进入战斗、暂停、等待选择、结束四种状态的回血归属，测试不会双倍治疗、覆盖受伤或在后台偷偷回血。

### 6.3 旧技能不能直接照搬

当前正式 PVE 有治疗、疾速、瞬间满蓄和自动弹反，测试场没有技能操作。以下为接入建议，尚未视为用户确认：

| 技能 | 建议适配 |
|---|---|
| 治疗 | 走同一个治疗入口，更新 HP 和显示；保留消耗与跨层技能点规则 |
| 疾速 | 按每个模拟时间步累计蓄力；不会突然跳进度或到期倒退，不加快手势长按识别 |
| 瞬间满蓄 | 进入满蓄待释放状态，仍要上划松手确认；不能恢复旧版自动攻击。取消是否消耗这次技能另行明确 |
| 自动弹反 | 仅在攻击范围已经命中时处理；是否豁免防御朝向和返还／消耗 AP 必须明确定义 |

技能入口可能破坏“双按钮专注操作”。技能交互及其去留未决定时，保持旧正式 PVE可用，新引擎停留在训练场或独立的正式数据预览入口；不得直接隐藏技能后宣称完整迁移完成。

## 8. 这份任务需要审阅的设计决定

| 决定 | 建议 | 影响 |
|---|---|---|
| 先做多大范围 | 先交付 M1，再按兼容项推进 M2～M4 | 先改善可维护性，不把所有新设计塞进一次改动 |
| PVP怎么处理 | 保持当前模式和协议，空间 PVP另开任务 | 不要求两边同时迁移；目前的共享判定架构会暂时分开 |
| 旧技能怎么处理 | 本轮先不为它们新增操作手势；在正式切换前单独决定保留方式 | 不会把“四个技能按钮”未经讨论直接塞回双按钮界面 |
| 正式 PVE数值基准 | 训练场保持当前固定数值；正式模式读取成长，另审阅伤害曲线、格挡基础倍率和蓄力词条映射 | 操作迁移不等于把全部角色改成 120 HP、18 点攻击 |
| 同步致命事件 | 正式模式建议沿用“同次结算双方死亡则败北”，明确同一步多个攻击的顺序；训练回归先保留原型顺序 | 需要专门测试，避免因函数调用顺序产生胜负变化 |
