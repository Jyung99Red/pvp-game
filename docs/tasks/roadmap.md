### 1.1 等用户在手机上试的

- **转镜头**（2026-10-08）：手指在画面上（不在摇杆区和按键上）横着拖，镜头绕主角水平转，能转一整圈；往右拖是往右看。电脑上按住鼠标拖。
  按着摇杆转镜头，人跟着拐（往上推永远是离开镜头的方向）；左手推摇杆、右手转着镜头时直接按攻击或格挡，键照样按得下去，镜头停在那里。
  看：转得快慢（`input.turn`，现在拖 200 像素约 80°）、方向顺不顺手（要反过来就说）；右手拇指在按键附近会不会误转；打怪时转镜头碍不碍事；对战里试一局。
  **镜头的角度、视角、距离**（同一天）：用户用滑块定了俯角约 58°、视角 30°、距离 16（`camera.pitch` 1.01、`fov` 30、`distance` 16；原来 0.96、34、13.2）。越肩那样的低角度不做（用户：主角有自己的视野规则）。
  这一组看到的范围和原来差不多（往前 7.0 格、往后 4.1 格、左右各 9.8 格），透视更平、更俯视，人物小约 6%。用户主要想看得多：要看得多就加距离（距离 19 约往前 8.1、往后 4.9、左右 11.6，人物再小 16%；视角开回 34° 也差不多是这个范围，透视更强一点）。
  **滑块先留着**（用户）：画面下方、帧率那一行上面三个，俯角（0.5 到 1.4，旁边写着角度和要填进参数的数）、视角（12° 到 60°）、距离（8 到 40 格，菜单的近中远照样乘在上面）；不存档，刷新回到上面的默认值。
  以后要拿掉：`partials/game.html` 的 `hud-tilt`、`style.css` 的同名样式、`ui/app.js` 里标着 Temporary 的那段、`view.render` 的 `pitch`、`fov`、`distance`。
  拖的时候留意：越低看得越远、人物越立体，但地上的红区越扁，墙和柱子挡掉的地面越多（千柱窟里最明显）；低到约 0.8（46°）以下，远处两个角的太阳影子会够不着（0.7 时差约 2 格），定下角度后再看要不要加大影子范围。
  **挡在前面的树冠**（同一天，用户定的办法）：地图里的树不动，树叶变透的范围加大（`graphics.leaves.reach` 1.3 → 2），而且叶子越靠近镜头透得越宽（新参数 `widen` 0.5：每靠近镜头 1 格多透 0.5 格）。
  训练场把镜头转到北、东、西，曙光村转到东边，贴着墙走：以前树冠盖住画面下半部，现在人物周围的地面透得出来，树干和淡淡的叶子还在。
  看：透的范围够不够、会不会太大（原野里站在一棵树的北边，默认视角下整棵树冠都是半透的；往旁边走 5 格它才是实的）；怪的红区在树下看不看得清；透到 25% 合不合适。
  **地图还没跟着改**，等用户试过再定。转到北、东、西三面看到的：
  原野头目院子北面的岩脊 6 到 7 格高，镜头在北边、人贴北墙时整个被挡住（遮挡透明会打开）；别处的岩脊从它那一侧看是画面下方一片石头，能玩；

  训练场、竞技场、原野的南边墙外是空草地，灰岩谷南边是 2 格高的平石台，从北面看比别的三面空；千柱窟和测试洞窟四面一样，不用改。

### 4.1 浏览器测试的写法

- 启动：`chromium.launch({ args: ['--use-gl=angle', '--use-angle=swiftshader', '--enable-unsafe-swiftshader'] })`。

### 4.4 three.js

`npm pack three@<版本>` 后用 esbuild 打成一个压缩文件（`npx esbuild <入口> --bundle --minify --format=esm`），放进 `vendor/three/`。

渲染器本身支持光照探针网格（着色器里的 `USE_LIGHT_PROBES_GRID`），打包里没有的只是 GPU 烘焙用的类；
`render/terrain_mesh.js` 自己造一个带 `isLightProbeGrid` 的对象交给渲染器，探针在 CPU 上沿方块网格烘焙（`render/terrain_light.js`），所以不用重新打包 three.js。

### 4.6 地图预览页 `map.html`

- 只读，不是编辑器。`mapview/plan.js` 把地图变成画图和描述用的数据（不碰页面，Node 测试直接跑），走游戏同一个加载函数，所以看到的就是游戏加载的；
  `mapview/page.js` 是页面和 2D 画布。
- 用法：选地图（或地址加 `?map=field`）；上边和左边是列号、行号（列从西边 0 往东，行从北边 0 往南）；指到哪格显示 `field (23, 5) 野狼 w`，
  点一下得到 `field (23, 5)`，拖一个框得到 `field (20,10)-(30,15)`，自动复制。
- 可开关的显示：怪物的警戒圈和追击圈、传送门去哪和过来站哪、建筑宝箱出生点木桩、一屏范围（手机横屏看得到的地面）、量距离。
- **总览**（下拉框第一项，或 `?map=world`）：游戏里各区域是各自独立的地图，没有全局坐标，这里按传送门的方向把它们摆到一张纸上。
  连线是一对传送门，虚线是要先打倒首领的，粉色是两头方向对不上的。点一块区域打开那张图。
- 游戏会拒绝的地图照样画出来，错误用红字写在旁边。
- **画图时要留意的**（经验，不是规定；都是按镜头在正南说的，镜头能转以后四面都要转过去看一眼，边界怎么改还没定，见第 1.1 节）：屏幕往北看得到约 7 格、往南约 4 格，入口放南边、目标放北边比较顺；
  玩家南边的高墙会一直触发镜头透视，南侧的边界用矮的；树冠半径 2 格，会盖住下面的人和怪，树不要种密、不要种在路上；
  狼王比一格宽，它要去的地方口子至少两格；断崖只看得见朝南的崖壁，崖线要画得参差；
  到达点和出生点离每只怪要有"发现距离 + 2.5 格"（测试检查）；改了宝箱的位置，存档里的宝箱记号跟着变。
- 测试：`tests/mapview.test.cjs`。
