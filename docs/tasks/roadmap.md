### 1.1 等用户在手机上试的

- **两张新地图**：晨雾原野和灰岩谷的布局、怪物位置、边界（岩脊、断崖、木栅栏）；原野变大后帧率有没有掉。
- **怪物**：隔着 2 格以上的墙走近没反应；被追时绕到墙后，怪会绕过来；三只以上的狼只有两只同时出招（灰岩谷东岸把两对狼引到一起最容易看出来）。
- **视野**：身边 2 格的小圈够不够、会不会太大；背后的方块、花草、石头跟着地面变暗看着对不对；对战里绕背还有没有用。
- **格挡和弹反的姿势**：格挡的蹲姿和前倾在手机镜头下看着对不对；完美弹反后往前推有没有力（弹出去、顶住、慢慢收）。姿势可以在 `tune.html` 的"其他姿势"里直接调。
- **野狼的撕咬**：前冲改短以后，从最远处及时后退躲得开，会不会又变成"退一步就躲开"。
- **对战**（两台设备）：加入的那一台走路和出招卡不卡；切到后台再回来能不能接着打；格挡 120° 侧面会不会太容易漏。
- **画质**：各地区的颜色会不会太过；各地区走一圈看帧率。
- **昼夜**：地址加 `?hour=21` 从晚上 9 点开始看（`?hour=7.5` 日出、`?hour=18.5` 日落）。夜里野外够不够亮、颜色偏蓝会不会太过；日出日落的暖光够不够；影子转动时边缘会不会一跳一跳。
- **火把的影子**：千柱窟里举火把绕柱子走，柱子和怪的影子对不对、边够不够柔；贴着怪打的时候影子还跳不跳，手的晃动是不是太少；帧率比以前掉多少（省电模式也开着火把影子，低端手机重点看这里）。点着枯木丛，周围有没有被火照亮。

- **画质加强**（2026-10-06）：
  - 天空可见度：原野树冠底下、灰岩谷两墙之间的窄道、曙光村房子和墙脚，有没有渐变地暗下去；切换区域有没有明显变慢（这几项加起来，电脑上原野从约 35 毫秒变成约 70 毫秒）。
  - 画质：菜单"画质"换成"极高"，影子边缘有没有锯齿、走路时闪不闪，帧率掉多少；"清晰"的像素比试过 3（45 帧），已改回 2（稳 60 帧）。
  - 自定义画质：菜单"设定"里把"画质"点到"自定义"，下面每项一个滑块，看着帧率那一行调（菜单开着时也显示；菜单里的人物也在画，帧率比关上菜单时低一点）。找到稳定的组合告诉我，可以定成清晰或极高的默认值。
  - 反弹光现在三档都是"逐顶点"（看起来和逐像素一样，花费小得多），看草地旁的绿还在不在。
  - 水面：原野中间的水潭白天、黄昏（`?hour=18.6`）、夜里（`?hour=23`）看着像不像水；看得见水底吗；举火把站在岸边，水面上那片暖光够不够。
  - 方块光：千柱窟举火把站在柱子转角，转角另一边的墙和地有没有淡淡的暖光；隔着厚墙是不是黑的；走动时卡不卡。
  - 反弹光：草地上的角色、石块的底部有没有带一点绿；会不会让整体太亮、太绿。

地图重画后，旧存档里的采集记录和新位置对不上；看到奇怪的现象就在菜单里"重新开始冒险"。

约定（也在 `AGENTS.md`）：

- 改动直接提交并推送到 `main`，不另开分支（用户）。
- **不擅自加功能**（用户）：用户没提的功能、已定规则的改动，先问再做。
- 可调数值只放 `game_config.js`，改了同步 `parameters.md`。模型形状和关键姿势是 `models/` 里的数据，不是可调数值。
- 新脚本登记到 `client-assets.json`；新页面片段还要在它那一页（`index.html`、`tune.html` 或 `map.html`）里加 `#mount-<id>`。
- 完成 = `node --test "tests/*.test.cjs"` 全绿。改了测试断言的内容要说明为什么。
- 代码注释和 `AGENTS.md` 用英文；`README.md`、界面文字、`docs/tasks/` 用中文。
- 文档只有 3 份（这份、`design.md`、`parameters.md`），都要短，只写现在：`design.md` 写游戏是什么和定下来的规则，
  这份写进度、接下来和怎么测。不写怎么实现、改过几次；新决定写进 `design.md` 对应的节。

在哪儿跑决定了浏览器怎么用：

- **用户的 Windows 电脑**（Claude 桌面版）：没装 Playwright，`tests/browser-smoke.test.cjs` 的 8 条会跳过。

  要跑浏览器测试：把 `playwright-core` 装在任意目录，设 `PLAYWRIGHT_MODULE=<该目录>/node_modules/playwright-core` 和 `PLAYWRIGHT_CHANNEL=chrome`。
- **云端容器**：预装了 Chromium 和 Playwright（`/opt/node22/lib/node_modules/playwright`），无头模式用软件渲染，浏览器测试能跑。

### 4.1 浏览器测试的写法

- 启动：`chromium.launch({ args: ['--use-gl=angle', '--use-angle=swiftshader', '--enable-unsafe-swiftshader'] })`。
- 横屏手机：`browser.newContext({ viewport: { width: 844, height: 390 }, hasTouch: true, isMobile: true, deviceScaleFactor: 2 })`。
- 多点触控要开 CDP 会话用 `Input.dispatchTouchEvent`（`page.touchscreen.tap` 只能单点）。
- **不要依赖真实时间**：无头模式两帧之间有时隔半秒以上（游戏的时钟会把太长的一帧截短，所以是变慢而不是跳）。
  用 `game.pause()` 停掉实时时钟、`game.run(秒)` 确定地推进。
- `tests/browser-smoke.test.cjs` 就是这套办法，找不到 Playwright 时自动跳过。设 `SMOKE_SHOTS=<目录>` 会存截图。

### 4.2 页面上的 `window.game`

- `game.pause()`、`game.run(秒)`、`game.sim`（模拟状态）、`game.map`（当前图）、`game.panel`（打开的面板）、`game.screens`（背包等界面）。
- `game.load('base' | 'field' | 'valley' | 'cave' | 'clearing')` 换区域，`game.save` 是存档，`game.persist()` 立刻写存档。地址里 `?map=` 直接进某个区域。
  地址里 `?hour=21` 让画面从那个钟点开始走（只是画，不进存档）；`dayKit.hourOf(game.sim)` 是存档里的真实时刻。
- `game.duel` 是对战会话，`game.room` 是房间界面；对战页面不要 `game.pause()`（对局靠真实时间）。
- `game.view.ground.cut.on.value = 0` 关掉镜头遮挡透明。
- 看模型近景：先 `game.view.render(game.sim, 0)`，再把 `game.view.render` 换成空函数，自己摆 `game.view.camera` 并 `game.view.renderer.render(game.view.scene, game.view.camera)`。
- 摆场面：直接改 `game.sim.player` 和 `game.sim.monsters[i]` 的位置、朝向、`phase`，再 `game.run(0.02)` 画出来；
  临时改地形用 `terrainKit.set(game.sim.terrain, 列, 行, 种类, 高度)`，试完要改回去（不然会进这个浏览器的存档）。
- 怪物测试用固定的场地 `tests/fixtures/m3-field.cjs`（游戏里的区域会跟着内容改，测试场地不变）。

### 4.3 两台设备的对战

- 同一个浏览器开两个页面，地址都带 `?link=local`，从界面建房、加入、打到结算。
- 真的 PeerJS 加 WebRTC：在临时目录 `npm install peer`，起 `PeerServer({ port, host: '127.0.0.1', path: '/' })`，
  两个页面放在不同的浏览器上下文里，地址带 `?peer=127.0.0.1:<端口>`。改了 `net/link.js` 时手动跑一遍。

### 4.4 three.js

`npm pack three@<版本>` 后用 esbuild 打成一个压缩文件（`npx esbuild <入口> --bundle --minify --format=esm`），放进 `vendor/three/`。

渲染器本身支持光照探针网格（着色器里的 `USE_LIGHT_PROBES_GRID`），打包里没有的只是 GPU 烘焙用的类；
`render/terrain_mesh.js` 自己造一个带 `isLightProbeGrid` 的对象交给渲染器，探针在 CPU 上沿方块网格烘焙（`render/terrain_light.js`），所以不用重新打包 three.js。

### 4.5 动作调试页 `tune.html`

- 电脑上用，只调主角。`tune/lab.js` 是工作台（不碰页面和 three.js，Node 测试直接跑），`tune/view.js` 只画，`tune/panel.js` 是页面。
- 身体每一帧都自动落地，所以 `base`、`pelvis` 的上下位移没有效果，蹲低只能靠弯腿。
- 骨头的三个数是欧拉角（`Ry · Rx · Rz`），滑块绕的不是骨头自己的轴，手腕这类关节单拖滑块摆不到想要的角度；
  所以每根骨头另有"绕自身轴"X / Y / Z，按住左右拖就绕画面上那三根线转。两个关键姿势之间仍是三个数各自线性过渡，摆完要在预览里看一眼中间过程。
- 节奏能实时改，是因为这一页加载 `game_config.js` 时不冻结（`window.unfrozenConfig`）；游戏和测试里照常冻结。
- 草稿存在这台电脑的浏览器里，只记和文件不同的地方。每次打开都读最新的文件：已经写回的项自动清掉，文件后来又改过的项以文件为准并提示。
- **用户贴回导出的代码时**：招式那段整段替换 `models/player_moves.js` 里同名的招，节奏那行替换 `game_config.js` 里同名的行（还要同步 `parameters.md`），
  其他姿势按注释里的位置放。然后跑测试：用户有意改了一招的形状时，`tests/hits.test.cjs` 里这招的扫角、起止方向可能要跟着改，改了要说明是用户定的。
- 测试：`tests/tune.test.cjs`。页面上的 `window.tune` 给测试和控制台用。

### 4.6 地图预览页 `map.html`

- 只读，不是编辑器。`mapview/plan.js` 把地图变成画图和描述用的数据（不碰页面，Node 测试直接跑），走游戏同一个加载函数，所以看到的就是游戏加载的；
  `mapview/page.js` 是页面和 2D 画布。
- 用法：选地图（或地址加 `?map=field`）；上边和左边是列号、行号（列从西边 0 往东，行从北边 0 往南）；指到哪格显示 `field (23, 5) 野狼 w`，
  点一下得到 `field (23, 5)`，拖一个框得到 `field (20,10)-(30,15)`，自动复制。
- 可开关的显示：怪物的警戒圈和追击圈、传送门去哪和过来站哪、建筑宝箱出生点木桩、一屏范围（手机横屏看得到的地面）、量距离。
- **总览**（下拉框第一项，或 `?map=world`）：游戏里各区域是各自独立的地图，没有全局坐标，这里按传送门的方向把它们摆到一张纸上。
  连线是一对传送门，虚线是要先打倒首领的，粉色是两头方向对不上的。点一块区域打开那张图。
- 游戏会拒绝的地图照样画出来，错误用红字写在旁边。
- **画图时要留意的**（经验，不是规定）：屏幕往北看得到约 6.5 格、往南只有约 3 格，入口放南边、目标放北边比较顺；
  玩家南边的高墙会一直触发镜头透视，南侧的边界用矮的；树冠半径 2 格，会盖住下面的人和怪，树不要种密、不要种在路上；
  狼王比一格宽，它要去的地方口子至少两格；断崖只看得见朝南的崖壁，崖线要画得参差；
  到达点和出生点离每只怪要有"发现距离 + 2.5 格"（测试检查）；改了宝箱的位置，存档里的宝箱记号跟着变。
- 测试：`tests/mapview.test.cjs`。
